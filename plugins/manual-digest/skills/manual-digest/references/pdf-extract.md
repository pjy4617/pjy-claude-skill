# PDF 추출 가이드

PDF 매뉴얼은 이 스킬에 동봉된 **`assets/pdf_extract.py`** 로 처리한다. PyMuPDF(`fitz`) 위에서
도는 로컬 스크립트이며, `pip install pymupdf` 휠 하나로 Windows/Linux/macOS 모두에서 동작한다.
외부 MCP 서버나 poppler 설치가 없어도 기본 경로가 성립한다.

핵심 원칙은 하나다. **큰 PDF를 통째로 읽지 않는다.** 목차로 뼈대를 훑고, 검색으로 어느
페이지인지만 먼저 확인한 뒤, 그 페이지만 연다. 지도를 보고 목적지만 찾아가는 것과 같다.

```bash
S="${CLAUDE_SKILL_DIR}/assets/pdf_extract.py"   # 호출 시 실제 절대 경로로 치환된다
# Windows에서 `python3`가 MS Store alias로 exit 49면 `py -3` 또는 `python`으로 대체한다 (exit 2와 혼동 금지 — 49는 파이썬 자체가 없는 것)
python3 "$S" --help
```

## 추출 경로 폴백 사다리 (순서 고정)

| 단계 | 경로 | 사용 조건 |
|------|------|-----------|
| L1 | `pdf_extract.py` (PyMuPDF) | 기본 경로 |
| L2 | `pdftotext -layout` (poppler) | L1이 exit 2(PyMuPDF 미설치)이거나 텍스트가 비었을 때 — **건너뛰기 금지** |
| L3 | `pdf_extract.py render` → 페이지 이미지 육안 판독 | L1·L2가 **둘 다** 실패했을 때만 |

**금지 1: L1 실패를 곧바로 "이 PDF는 텍스트 레이어가 없다"로 판정하는 것.**
스캔본 판정은 `info`의 표본 판정과 **L2까지 실패**한 뒤에만 내릴 수 있다.

**금지 2: exit 2를 PDF 문제로 읽는 것.** exit 2는 "이 환경에 PyMuPDF가 없다"는 뜻이지
"이 PDF가 이상하다"가 아니다. `pip install pymupdf`를 안내하고 그 자리에서는 L2로 진행한다.

### 종료 코드

| 코드 | 뜻 | 대응 |
|------|-----|------|
| 0 | 정상 | 그대로 진행 |
| 1 | 사용자 오류 (파일 없음·페이지 범위 초과·표기 오류) | 메시지대로 인자를 고친다. 폴백 대상이 아니다 |
| 2 | PyMuPDF 미설치 | `pip install pymupdf` 안내 + 그 자리에서는 L2로 진행 |

### 실측 근거 (재발 방지)

`invalid horizontal advance` 에러로 텍스트 추출이 통째로 실패한 PDF 3건(TI 데이터시트
SLOS068AB, XGZP6859A 도면, Cosmo 데이터시트)을 `pdftotext`와 PyMuPDF로 재시도한 결과
**3건 모두 텍스트가 정상 추출**됐다. 즉 그 에러는 PDF 손상 신호가 아니라 당시 쓰던 추출
도구의 폰트 메트릭 파싱 버그였다. 비유하자면 책이 찢어진 게 아니라 스캐너가 고장 난 것이다.

한 도구의 실패를 스캔본으로 오판하면 L3(이미지 판독)로 직행하게 되는데, 이 경로는
① 토큰이 페이지당 수십 배 비싸고 ② 표의 수치를 사람이 눈으로 옮겨 적는 것과 같아
**행을 잘못 짚을 위험이 텍스트 추출보다 구조적으로 높다**.

### 추출 경로 기록

`digest.md` 프론트매터의 `extractor`에 **실제로 사용한 경로**를 적는다.

| 값 | 의미 |
|------|------|
| `pymupdf` | L1 — `pdf_extract.py` (기본) |
| `pdftotext-layout` | L2 — poppler 폴백 |
| `page-render` | L3 — 페이지 이미지 육안 판독 |

L3(`page-render`)를 쓴 경우에는 **"수치는 육안 판독본이라 원본 대조가 필요하다"는 문장을
다이제스트 개요에 남긴다** — 읽는 쪽이 신뢰도를 알아야 하기 때문이다.

## 서브커맨드

| 명령 | 용도 |
|------|------|
| `info <pdf>` | 메타데이터·페이지 수·목차 유무·페이지 라벨·텍스트 레이어 표본 판정 |
| `toc <pdf> [--heuristic] [--min-size N]` | 목차 — 내장 outline 우선, 없으면 글꼴 크기 휴리스틱 |
| `text <pdf> --pages "7-12,82" [--sort]` | 지정 페이지 본문 (혼합 범위) |
| `tables <pdf> --pages "6"` | 지정 페이지의 표를 마크다운 표로 |
| `find <pdf> "<query>" [--context N] [--max N]` | 대소문자 무시 검색 → 페이지 열지도 |
| `render <pdf> --pages "1" --dpi 110 --out DIR` | 페이지 PNG 렌더 (L3 육안 판독 전용) |

모든 서브커맨드가 `--json`을 받는다. 페이지 번호는 전부 **1-based 물리 페이지**다.

### 페이지 인자 형식

| 형식 | 예시 | 의미 |
|------|------|------|
| 단일 | `"7"` | 7페이지만 |
| 범위 | `"7-12"` | 7~12페이지 |
| **혼합 범위** | `"7-12,28-30,82-83,166"` | 산발적 페이지를 한 번에 — **토큰 효율 결정적** |

## 인제스트 절차

### 1. `info` — 한 번만 호출한다

```bash
python3 "$S" info "<abs>"
```

돌아오는 것: 제목/저자/생성 도구/생성일, 페이지 수, 암호화 여부, **내장 목차(outline) 유무와
항목 수**, 페이지 라벨(인쇄 표시 번호) 유무, 그리고 텍스트 레이어 표본 판정.

표본 판정은 서로 떨어진 5페이지의 글자 수를 세어 평균이 50자 미만이면 `스캔본 의심`,
아니면 `텍스트 있음`으로 찍는다. **`스캔본 의심`은 판정이 아니라 신호다** — L2로 교차 확인한
뒤에 확정한다.

### 2. `toc` — 목차를 받는다 (여기서 토큰이 가장 크게 절약된다)

```bash
python3 "$S" toc "<abs>"                 # outline 있으면 outline, 없으면 자동으로 휴리스틱
python3 "$S" toc "<abs>" --heuristic     # outline이 있어도 휴리스틱으로 강제 복원
```

첫 줄에 **어느 경로를 썼는지** 찍힌다 (`경로: PDF 내장 outline — 28항목` /
`경로: 휴리스틱 (본문 글꼴 10.0pt, 제목 임계 12.0pt) — 72항목`). 이 줄을 인제스트 로그에 남긴다.

**"첫 5-10페이지를 읽어 TOC 페이지를 찾는" 옛 절차를 쓰지 않는다.** WOS 매뉴얼(68p, Word 생성,
outline 없음) 실측 기준으로 앞 5페이지 본문은 19,442자였고, 같은 문서의 `toc` 출력은
**72줄·약 3 KB**다. 6배 이상 싸고, 결과는 목차 페이지보다 정확하다(목차 페이지에 빠진 절도 잡는다).

휴리스틱은 두 조건을 **모두** 만족하는 줄만 제목으로 본다.
① 글꼴 크기가 본문보다 크다(기본: 본문 + 2pt 이상) ② 번호 절 패턴으로 시작한다(`3 개요`, `3.1.2 설정`).
본문 글꼴 크기는 글자 수로 가중한 최빈값이다. 목차 페이지의 항목은 대개 본문 글꼴이라 ①에서
자동으로 걸러진다. 임계값을 직접 주려면 `--min-size 13.5`처럼 절대 pt로 지정한다.

### 3. `text` — 섹션 도입 페이지만 연다

```bash
python3 "$S" text "<abs>" --pages "9,14,16,21,35,44"        # 혼합 범위로 한 번에
python3 "$S" text "<abs>" --pages "42" --sort               # 다단 조판이면 읽기 순서 정렬
```

**모든 페이지를 읽지 않는다.** 각 §의 도입 1-2페이지 + 핵심 개념·표 페이지만.
절차/대화상자 섹션은 `toc` 제목만으로 요약이 충분하다. 목표 커버리지 ~20%.

### 4. `tables` — 표가 핵심인 페이지만

```bash
python3 "$S" tables "<abs>" --pages "6"          # 마크다운 표
python3 "$S" tables "<abs>" --pages "6" --json   # 셀 배열
```

데이터시트의 전기적 특성표처럼 **행/열을 정확히 맞춰야 하는 페이지**에 쓴다. 표가 없는
페이지는 `--- p.N --- 표 없음`으로 명시된다(조용히 비지 않는다). 페이지 전체 본문 대신 표만
받으므로 그만큼 싸다 — TI 데이터시트 p.6 실측: 51행×7열 표 하나가 54줄로 나온다.

### 5. `find` — 핀포인트는 열지도부터

```bash
python3 "$S" find "<abs>" "V-suffix"                     # 페이지 번호 + 건수만
python3 "$S" find "<abs>" "V-suffix" --context 40 --max 5 # 스니펫까지
```

기본 출력에는 **본문이 들어 있지 않다.** "어느 페이지에 몇 건 있다"만 받고, 그다음
`text --pages`로 그 페이지만 연다. 검색어가 흔한 단어면 매치가 수백 건이 되므로 `--context`를
먼저 붙이지 않는다.

### 6. 페이지 포인터 정확도

페이지 번호는 **PDF 내부 물리 인덱스** 기준이다. 인쇄 표시 페이지가 다를 수 있다(로마자
서문 등). `info`의 `페이지 라벨` 항목이 `있음`이면 `toc` 출력이 `p.9 (표시 iii)` 형태로
두 번호를 함께 보여준다. 다이제스트에는 조회에 쓸 물리 페이지를 기준으로 적는다.

## 대형 PDF (1000p+)

`toc`와 `find`는 전 페이지를 훑지만 출력이 작아 그대로 쓴다(PyMuPDF 전체 텍스트 추출 실측:
68p에 0.04초). 비용이 드는 것은 `text`이므로, 여기서만 페이지를 나눈다.

```bash
python3 "$S" text "<abs>" --pages "12,45,88"      # 섹션 도입만
python3 "$S" text "<abs>" --pages "300-305"       # 필요한 구간만
```

진행률을 사용자에게 표시하여 체감 시간을 줄인다.

## L2: pdftotext 사용법 (폴백)

```bash
command -v pdftotext || echo "poppler 미설치"   # 먼저 가용성 확인

pdftotext -layout -enc UTF-8 "<abs>" -                    # 전체를 stdout으로
pdftotext -layout -enc UTF-8 -f 82 -l 83 "<abs>" -        # 82~83페이지만
```

- **`-layout`은 필수다.** 이 옵션이 없으면 표의 열 정렬이 무너져 어느 행의 값인지 알 수 없게 된다.
- `-f`/`-l`은 각각 시작·끝 페이지(1-based). 산발적 페이지는 호출을 나눈다(혼합 범위는 L1 전용).
- 출력을 통째로 받지 않는다 — `| sed -n '120,180p'` 또는 `| grep -n -A5 "<섹션 제목>"`으로 구간만.
- **Windows**: poppler가 기본 포함되지 않는다. L1(PyMuPDF)이 표준 경로인 이유가 이것이다.
  L2까지 못 쓰면 "판정 불가"이지 "스캔본"이 아니다.

## 텍스트 레이어 없는 스캔 PDF

**스캔본 판정은 L1·L2를 모두 거친 뒤에만 내린다.**

1. `info`가 `스캔본 의심`을 찍거나 `text`가 빈 결과 → 아직 판정하지 않는다
2. `pdftotext -layout`(L2)로 **서로 떨어진 3페이지 이상**을 표본 추출
3. 표본 전체가 페이지당 50자 미만이면 그때 스캔본으로 확정
4. L2가 정상 텍스트를 내면 스캔본이 아니다 — L2를 정식 추출 경로로 삼아 인제스트를 계속한다

스캔본으로 확정된 경우에만 "OCR 필요, V2 이후 지원" 명시 후 인제스트 중단.
poppler 미설치로 L2를 못 돌린 경우는 "판정 불가"이지 "스캔본"이 아니다 — 설치를 안내한다.

## 한계 (알고 쓴다)

- **Word로 만든 PDF의 표는 과분할될 수 있다.** 셀 경계를 선이 아니라 여백으로 잡는 문서에서
  `tables`가 열을 잘게 쪼갠다 (실측: WOS 매뉴얼 p.42의 2열 표가 50행×4열로 나왔다).
  표가 어색하면 같은 페이지를 `text`로도 열어 대조한다. TI 데이터시트처럼 괘선이 있는
  표는 정확하다(51행×7열 셀 단위 일치).
- **휴리스틱 목차는 번호 없는 제목을 못 잡는다.** "Introduction"처럼 번호가 없는 절, 그리고
  번호 체계가 문서마다 다른 경우가 그렇다. 이때는 `find`로 알려진 제목을 찾아 보완한다.
- **스캔본 OCR은 지원하지 않는다.** tesseract가 필요하며 V2 이후 과제다.
- **PyMuPDF는 외부 의존성이다.** `pip install pymupdf` 한 줄이지만 설치할 수 없는 환경이
  있을 수 있고, 그때가 L2가 존재하는 이유다. 라이선스는 AGPL이며 여기서는 로컬 CLI 도구로
  호출할 뿐이라 배포물에 코드가 섞이지 않는다.
