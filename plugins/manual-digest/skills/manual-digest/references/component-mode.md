# 부품 모드 (`--component`)

부품 데이터시트를 **전역 공용 자료**로 등록하고, 같은 부품이 다시 들어올 때 중복·개정판을 가려낸다.
KiCad 심볼·풋프린트·3D 모델은 복사하지 않고 **어디에 있는지만** 기록한다.

비유: 다이제스트 폴더는 회사 공용 자료실이다. 부품 카드(다이제스트)와 원본 책(PDF)은 자료실에 두고,
실물 부품(KiCad 파일)은 원래 서랍(KiCad 라이브러리)에 둔 채 카드에 "몇 번 서랍"만 적는다.

## 1. 무엇을 부품 모드로 등록하나

| 부품 모드 (전역) | 일반 모드 (프로젝트) |
|---|---|
| 부품 데이터시트, 레퍼런스 매뉴얼(RM), 정오표, 앱노트, 레이아웃 가이드 | 보드 회로도(평가보드 포함), 장비 사양서, PRD, 코드베이스 |

판단 기준은 하나다 — **다른 프로젝트에서도 같은 내용이 사실인가.** 그렇다면 부품 모드다.
사용자가 `--component` 없이 "이 데이터시트 등록해줘"라고 하면, 입력이 부품 데이터시트로 보일 때
부품 모드를 제안하고 사용자 답에 따른다.

## 2. 저장 규칙

- scope는 항상 `global` — `~/.claude/manuals/<id>/`. `--scope`를 줘도 무시하고 그렇게 알린다.
  옛 Rev를 특정 프로젝트에 묶어야 하는 경우만 예외다(4절 "따로 등록").
- 원본을 `~/.claude/manuals/<id>/source.<확장자>`로 **복사**한다. 링크는 쓰지 않는다(원래 파일이 지워지면 끊긴다).
  - `source` = 복사본 절대 경로 (핀포인트 조회가 쓰는 경로)
  - `origin` = 사용자가 준 원래 경로 (기록용, 사라져도 된다)
- 원본은 **최신 Rev 1개만** 둔다. 이전 Rev 파일은 버리고 `revisions`에 한 줄만 남긴다.
- `metadata.json`에 `kind: "component"`를 넣는다. 일반 매뉴얼과 같은 폴더·같은 INDEX.md를 쓰고 이 값으로만 구분한다.

## 3. ID 와 별칭

- ID = **제조사 품번의 기본형, 소문자.** 패키지·테이프·온도 접미사는 뺀다.
  예: `TPS2051CDBVR`는 `tps2051c`, `STM32C071RBT6`는 `stm32c071`, `LAN9252/ML`은 `lan9252`
- **시리즈 데이터시트**(한 PDF 가 여러 정격·품번을 다룸, 예: SMD1206 퓨즈 시리즈)는 ID = **주문한 품번**(`--lcsc` 가 가리키는 것, 없으면 사용자가 말한 것)의 기본형, 시리즈명은 별칭이다.
  같은 시리즈의 다른 품번을 나중에 등록하면 sha256 이 같아 `SAME_FILE` 로 잡히고 별칭 추가만 제안된다 — 같은 PDF 를 두 번 두지 않는다.
- 품번이 애매한 수동·범용 부품은 `<종류>-<핵심값>-<LCSC번호>` — 예: `xtal-48mhz-c6732651`
- `aliases` = 같은 데이터시트가 다루는 다른 품번(계열·주문 품번)을 소문자로. 예: `tps2051c`의 별칭 `tps2065c`, `tps2051cdbvr`.
  데이터시트 첫 페이지의 품번 목록과 주문 정보(Ordering Information) 표에서 뽑는다.
- 이렇게 지으면 INDEX.md를 열지 않고도 존재 여부를 확인할 수 있다:
  `ls ~/.claude/manuals | grep -i tps20` 또는 `grep -l '"tps2065c"' ~/.claude/manuals/*/metadata.json`

## 4. 등록 전 판정 (메인이 직접 한다)

워커에 위임하기 **전에** 메인이 판정한다. 사용자에게 물어야 할 수 있기 때문이다(워커는 질문할 수 없다).
전역과 현재 프로젝트의 `metadata.json`을 모두 본다. **아래 스니펫을 그대로 실행한다.** `ls`/`grep` 으로 대신하지 않는다 —
sha256 비교와 프로젝트 쪽 확인을 함께 하는 것은 이 스니펫뿐이고, grep 은 다른 파일명으로 들어온 같은 PDF 를 놓친다.

```bash
python3 - "<새 원본 절대 경로>" "<후보 id>" "<별칭1,별칭2>" <<'PY'
import glob, hashlib, json, os, sys
src, cid, aliases = sys.argv[1], sys.argv[2], {a for a in sys.argv[3].split(",") if a}
sha = hashlib.sha256(open(src, "rb").read()).hexdigest()
names = {cid} | aliases
for m in glob.glob(os.path.expanduser("~/.claude/manuals/*/metadata.json")) + glob.glob(".claude/manuals/*/metadata.json"):
    d = json.load(open(m))
    known = {d.get("id")} | set(d.get("aliases") or [])
    if d.get("sha256") == sha:
        print("SAME_FILE", d["id"], d.get("scope"), m)
    elif names & known:
        print("SAME_PART", d["id"], d.get("scope"), d.get("version"), m)
print("SHA", sha)
PY
```

| 결과 | 뜻 | 동작 |
|---|---|---|
| `SAME_FILE` | 완전히 같은 파일이 이미 있다 | "이미 있음: `<id>` (scope)"를 알리고 끝낸다. 후보 ID가 기존 ID·별칭에 없으면 **별칭 추가만** 제안한다 |
| `SAME_PART` | 같은 부품, 다른 파일 | 아래 "개정판 비교"를 보여 주고 사용자가 고르게 한다 |
| 출력 없음 | 새 부품 | 정상 등록 (5절) |

**개정판 비교.** 두 파일의 Rev와 날짜를 나란히 보여 준다.
- 새 파일: `pdf_extract.py info`의 메타데이터 + `pdf_extract.py text --pages 1`의 첫 페이지.
  Rev 표기는 제조사마다 다르다 — TI `SLVSxxx – REVISED MARCH 2024`, ST `DS12345 Rev 7`, Microchip `DS00001234C`.
  첫 페이지에 없으면 `pdf_extract.py find "<abs>" "Revision History"`로 개정 이력 표 페이지를 찾는다.
- 기존 파일: `metadata.json`의 `version`, `publication_date`.
- 읽지 못하면 파일 날짜와 페이지 수만 보여 준다. Rev를 지어내지 않는다.

선택지는 넷이다.

| 선택 | 언제 | 동작 |
|---|---|---|
| 갱신 | 새 파일이 더 최신 | 7절 `--update` 흐름으로 넘어간다 |
| 따로 등록 | 프로젝트가 옛 Rev에 묶여 있다 | 그 프로젝트 scope에 일반 모드로 등록. project가 global을 덮어쓰는 기존 규칙을 그대로 쓴다 |
| 다른 문서 | 앱노트·정오표처럼 사실 다른 문서였다 | ID에 접미사를 붙여 새로 등록 (`tps2051c-an`, `stm32c071-errata`) |
| 취소 | — | 아무것도 쓰지 않는다 |

## 5. 다이제스트 형식 (부품 전용 고정 섹션)

부품 데이터시트는 구조가 거의 같다. 섹션을 고정하면 요약이 고르고 작아진다.
워커 프롬프트에 이 절을 그대로 넘긴다. 없는 섹션은 지우지 말고 "데이터시트에 없음"이라고 적는다.
원본이 데이터시트가 아니라 기계 도면·승인서(approval sheet)면 "개요"에 원본 종류를 적고, 없는 섹션은 `원본에 없음 (기계 도면)`처럼 종류를 붙여 한 줄로 끝낸다. 섹션을 지어내 채우지 않는다.

```markdown
---
(SKILL.md 7단계 프론트매터 그대로) + 아래 3줄
kind: component
aliases: [<별칭>, ...]
origin: <사용자가 준 원래 경로>
---

# <품번> — <한 줄 기능> 다이제스트

## KiCad 파일
| 파일 | KiCad 이름 | 실제 위치 | 상태 |
|---|---|---|---|
| 심볼 | ... | ... | 있음/없음/위치 끊김 |
| 풋프린트 | ... | ... | ... |
| 3D 모델 | ... | ... | ... (제조사/상자 근사) |

## 개요
품번 변형, 패키지 변형, 제조사, Rev, 핵심 기능 3~5줄.

## 절대 최대 정격 [p.N]
## 권장 동작 조건 [p.N]
## 핀 기능 [p.N]
| 핀 번호 | 이름 | 종류(I/O/P) | 기능 |
## 핵심 전기적 특성 · 타이밍 [p.N]
## 응용 회로와 외부 부품 값 [p.N]
## 레이아웃 가이드 [p.N]
## 패키지 · 랜드 패턴 [p.N]
## 정오표 · 주의사항 [p.N]
## 키워드 인덱스
## 사용 가이드
```

**레이아웃 예시 그림은 글로 옮기고 그림 파일로 남긴다** (2026-10-24 추가). 글 추출(`pdftotext`)은 그림을 버린다.
"Layout Example" 절이 "개념도, 수치 없음" 한 줄로 끝나면, 그 다이제스트를 읽은 쪽은 원본을 다시 열 이유가 없어
그림에만 있는 정보(양쪽 입력캡 대칭, GND 구리·비아 배열, 내층 띠, 층 구성)를 통째로 놓친다
(실측: LMR36006 Figure 57 — 다이제스트만 본 보드가 왼쪽 VIN 핀 입력캡과 GND 방열 비아를 빠뜨렸다).
1. 레이아웃 예시·권장 랜드 그림이 있는 쪽을 `pdftoppm -f N -l N -png -r 110 source.pdf <id 폴더>/figNN-layout-pN` 으로
   렌더해 `<id 폴더>/` 에 둔다 (파일 이름에 그림 번호와 쪽).
2. "레이아웃 가이드" 섹션에 그 파일 이름을 적고, 그림이 보여 주는 것을 **부품 자리·비아·구리·층 순으로 글 목록**으로 옮긴다.
   좌표가 없어도 "어느 핀 옆에 무엇" 수준은 쓸 수 있다.
3. `index.md` 의 그 절 줄에도 그림 파일 이름을 붙인다.

**핀 기능 표는 빠짐없이 쓴다.** 샘플링 규칙(~20%)의 예외다. 8절의 KiCad 핀 대조가 이 표를 기준으로 한다.

**프로젝트 문구 금지.** 전역 자료에 "본 보드는 QSOP-16", "24V→5V 후보" 같은 문구가 남으면
다른 프로젝트가 그것을 사실로 읽는다. 데이터시트에 적힌 사실만 쓴다. 워커가 끝나면 메인이 검사한다:

```bash
grep -nE "본 보드|우리 보드|이 보드|후보|채택|우리 설계|본 설계" ~/.claude/manuals/<id>/digest.md
```

걸리면 그 줄을 지우거나 데이터시트 사실로 고쳐 쓴다. 지운 프로젝트 맥락은 그 프로젝트의
`.claude/manuals/INDEX.md`에 한 줄로 옮긴다: `global:tps2051c — 본 보드 QSOP-16, 5V 레일`

## 6. INDEX.md 한 줄

전역 INDEX.md는 부품이 수백 개로 늘어난다. 한 줄을 짧게 쓴다 — 제목 칸은 `[부품] <품번> <기능 10~20자> — <제조사>` 정도.
예: `| tps2051c | [부품] TPS2051C 전원 스위치 0.5A — TI | pdf | Rev F | global | [digest](tps2051c/digest.md) · [index](tps2051c/index.md) | |`

## 7. 갱신 — `--component --update <id> <새 원본>`

원본을 복사해 두므로 일반 `--update <id>`는 쓸모가 없다 — 복사본은 바뀌지 않아 항상 "변경 없음"이 나온다.
그래서 부품 모드의 갱신은 **새 원본 경로를 직접 받는다.**

1. 새 파일 sha256을 `source.*`와 비교한다. 같으면 "변경 없음"으로 끝낸다.
2. 다르면 새 파일의 **개정 이력(Revision History)** 을 먼저 읽는다
   (`pdf_extract.py find "<abs>" "Revision History"`로 페이지를 찾고 그 페이지만 `text`로 읽는다). 무엇이 바뀌었는지 사용자에게 보여 준다.
3. 워커에 위임해 다이제스트를 다시 만든다 (5절 형식).
4. `source.*`를 새 파일로 교체하고, `revisions`에 이전 Rev 한 줄을 추가한다.
5. 개정 이력에 패키지·랜드 패턴·기계 도면·핀 배치 변경이 있으면 **"풋프린트 재확인 필요"** 를 경고하고
   `kicad.warnings`에도 남긴다.
6. 끝에 "옛 Rev가 필요한 프로젝트는 그 프로젝트에 따로 등록하라"는 안내를 한 줄 붙인다.
   이 부품을 쓰는 프로젝트를 찾아 다니지는 않는다.

## 8. KiCad 파일 위치 — `assets/kicad_locate.py`

KiCad 파일은 **다이제스트 폴더에 복사하지 않는다.** KiCad는 라이브러리 표에 등록된 곳에서만 파일을 읽기 때문이다.
스크립트는 KiCad 자신의 라이브러리 표(`sym-lib-table`, `fp-lib-table`, KiCad 10의 중첩 표 포함)와
경로 변수(`kicad_common.json`의 사용자 변수, `KICAD<버전>_*_DIR` 기본 변수)를 읽어, KiCad가 찾는 것과 같은 경로를 본다.
경로를 플러그인에 박지 않으므로 별도 설정이 없다.

```bash
K="${CLAUDE_SKILL_DIR}/assets/kicad_locate.py"   # 이 파일에서는 치환되지 않는다 — SKILL.md 가 알려 준 절대 경로로 바꾼다
python3 "$K" locate --symbol <[lib:]이름> [--footprint <[lib:]이름>] [--model <경로>] [--project <dir>] [--json]
python3 "$K" verify ~/.claude/manuals/<id>/metadata.json [--json]
python3 "$K" --selftest
```

- `--symbol`만 주면 심볼의 Footprint 속성을 따라 풋프린트를 찾고, 풋프린트의 `(model ...)`을 따라 3D 모델을 찾는다.
- 라이브러리 이름을 빼면 모든 라이브러리에서 이름으로 찾는다. 표준 라이브러리의 심볼 이름은 주문 품번에 가깝다
  (`TPS2051CDBV`) — 기본형으로 못 찾으면 별칭으로 다시 찾는다.
- 출력 첫 줄이 상태 줄이다: `심볼 있음 1-pjy-lib:CH334R | 풋프린트 있음 Package_SO:QSOP-16_... | 3D 있음 ...`

### 등록 때 (5절 다이제스트가 끝난 뒤)

1. 품번과 별칭으로 `locate`를 돌린다. 사용자가 KiCad 이름을 알려 줬으면 그것을 쓴다.
2. 찾은 것은 `metadata.json`의 `kicad` 칸과 digest.md "KiCad 파일" 표에 적는다. 못 찾은 것은 `null`(= 없음)로 두고 **등록은 계속한다.**
3. 핀 대조 (경고만, 등록을 막지 않는다):
   - 스크립트가 심볼 핀 번호와 풋프린트 패드 번호를 자동 대조한다 (`warnings`)
   - 메인이 심볼 핀(`번호=이름`)을 digest.md 핀 기능 표와 대조한다. 번호는 같은데 이름이 다르면
     `핀 3: 데이터시트 EN, 심볼 GND` 형식으로 적는다. `~{EN}`(반전 표기) 같은 KiCad 표기 차이는 같은 것으로 본다
   - 경고는 `kicad.warnings`에 남기고 사용자에게 보고한다

### `--component --kicad <id> [--step <stp>] [--lcsc <코드>]` — 빠진 파일 만들기

사용자가 나중에 "ch334r 심볼 만들어서 등록해줘"라고 하면 실행한다.
**등록 명령에 `--step` 이나 `--lcsc` 가 붙어 있었으면 등록이 끝난 직후 이 절을 묻지 않고 이어 실행한다** — 같은 부품을 두 번 시키지 않게 하려는 옵션이다.

| 옵션 | 뜻 | 생성 스킬에 넘기는 값 |
|---|---|---|
| `--step <stp>` | 제조사 STEP 3D 모델 | **절대 경로로 바꿔** 넘긴다(전역 자료라 상대 경로는 다른 프로젝트에서 끊긴다). 생성 스킬이 자기 3D 폴더로 복사하고 회전·오프셋을 검산한다. 없으면 생성 스킬이 상자 근사를 만든다 |
| `--lcsc <코드>` | JLCPCB/LCSC 주문 코드(`C7603429`) | 코드 그대로. 심볼 `JLPCB` 필드에 들어가고, 생성 스킬은 이 코드로 EasyEDA 패드 치수를 먼저 받는다(도면 판독보다 정확). 이 스킬은 digest.md "KiCad 파일" 표에 `주문 코드` 줄로 적는다 |

`--lcsc` 만 있고 `--step` 이 없으면 3D 는 생성 스킬에 **상자 근사로 만들라고** 넘기고, `metadata.json` `kicad.model_kind` 에 `box` 로 적는다. 사용자가 "3D 는 없다"고 한 것은 빼라는 뜻이 아니다.

이미 등록된 부품(`SAME_FILE`)에 두 옵션이 붙어 오면 등록은 건너뛰고 이 절만 실행한다.

주문 코드의 품번 접미사가 도면 품번과 다를 수 있다(예: 도면 `-1Y-00A`, 주문 `-14-00Z`). 하우징이 같다고 보되 digest.md 에 **추정**이라고 적는다.

1. `verify`로 지금 상태를 본다. 빠진 것(없음/위치 끊김)만 대상이다.
2. **만드는 일은 이 스킬이 하지 않는다.** 데이터시트로 심볼·풋프린트·3D 모델을 만드는 스킬이
   사용 가능하면(스킬 목록에서 그런 설명을 가진 스킬을 찾는다) **`Skill` 도구로 그 스킬을 호출해** 맡긴다. 그 스킬의 문서·스크립트를 직접 읽어 실행하지 않는다.
   넘길 것: `source.*` 경로, digest.md의 핀 기능 표·패키지 절 위치, 빠진 항목, 이미 있는 항목의 KiCad 이름, **`--step` 경로, `--lcsc` 코드**(있을 때).
   생성 스킬이 심볼 필드(`Datasheet` = 이 다이제스트의 `source.*` 절대 경로, `JLPCB` = 주문 코드, `MPN`, `Manufacturer`)를 채우게 한다.
   라이브러리에 넣는 위치도 그 스킬의 규칙을 따른다.
3. 그런 스킬이 없으면 아무것도 만들지 않고 "부품 생성 도구 없음 — KiCad에서 만든 뒤 `--kicad <id>`를 다시 실행"이라고 안내한다.
4. 만든 뒤 생성 스킬이 알려 준 이름으로 `locate --symbol <lib:이름>`을 돌리고, 찾은 값을 `metadata.json` `kicad` 칸에 적는다.
   `symbol`/`footprint` 는 **문자열** `lib:이름`, `model` 은 풋프린트에 적힌 경로 문자열(`${KICAD_..._DIR}/…` 같은 변수 경로 우선, 없으면 절대 경로)이다 — dict 가 아니다.
   그다음 `verify`로 확인하고 핀 대조를 한다. 세 줄이 모두 "있음"이어야 끝이다.
   주의: `verify`는 **읽기 전용**이다. `kicad` 칸이 비어 있으면 exit 0 으로 "없음"만 낸다 — 칸을 채우는 것은 `locate` 결과를 적는 이 단계다.

사용자가 파일을 직접 받아 왔을 때(SnapEDA·제조사·JLC)도 같다 — 라이브러리에 넣는 일은 생성 스킬이나 사용자가 하고,
이 스킬은 들어간 뒤의 위치를 기록하고 대조한다. 외부 파일은 핀 번호가 틀린 경우가 흔하니 대조 경고를 꼭 보고한다.

## 9. 목록과 미리 판정

**`--component --list`** — `kind: component`인 항목마다 `verify`를 돌려 한 줄씩 보여 준다.

```
tps2051c   Rev F  심볼 있음 | 풋프린트 있음 | 3D 있음(제조사)
ch334r     Rev 1  심볼 있음 | 풋프린트 없음 | 3D 없음
lan9252    Rev E  심볼 있음 | 풋프린트 위치 끊김 | 3D 상자 근사
```

파일을 옮기거나 이름을 바꾸면 "위치 끊김"이 된다. 매번 다시 확인하므로 기록이 낡아도 목록이 거짓말을 하지 않는다.

**`--component --check <파일...>`** — 등록하지 않고 4절 판정만 한다. 파일마다 `이미 있음 / 개정판 있음 / 새 부품`을
표로 보여 준다. 여러 프로젝트의 데이터시트 폴더를 한꺼번에 옮기기 전에 쓴다. 아무것도 쓰지 않는다.

## 10. 위임 범위

| 작업 | 주체 |

| 4절 판정, 사용자 선택, 5절 프로젝트 문구 검사, 8절 위치 확인·핀 대조, `--list`, `--check` | 메인 (원본을 읽지 않거나 첫 페이지만 읽는다) |

| 빠진 KiCad 파일 만들기 (`--kicad`, `--step`/`--lcsc` 자동 연쇄 포함) | 부품 생성 스킬 (그 스킬의 실행 규칙을 따른다). 메인은 넘길 값을 모으고 끝난 뒤 `verify` 만 한다 |

## 11. 기존 프로젝트 다이제스트 이전 — `--component --migrate <프로젝트>`

이미 프로젝트 안(`<프로젝트>/.claude/manuals/`)에 만들어 둔 부품 다이제스트를 전역으로 옮긴다.
**요약을 다시 하지 않는다.** 폴더를 그대로 복사하고 메타데이터와 카탈로그만 고친다. 그래서 워커 위임도 없다.
비유하면 각 책상 서랍에 있던 부품 카드를 공용 자료실로 옮기고, 서랍에는 "자료실 몇 번 칸" 쪽지만 남기는 일이다.

대상은 **부품 데이터시트·RM·앱노트·정오표**뿐이다. 센서·장비 사용 매뉴얼, 보드 회로도, 평가보드 자료는 `keep`으로 남긴다.

```bash
M="${CLAUDE_SKILL_DIR}/assets/migrate_components.py"   # 치환되지 않는다 — SKILL.md 의 절대 경로로
python3 "$M" plan    <프로젝트>    # 1. 계획 초안 + 표 (아무것도 옮기지 않는다)
python3 "$M" apply   <프로젝트>    # 3. 계획대로 실행 (프로젝트 폴더는 남긴다)
python3 "$M" cleanup <프로젝트>    # 5. 전역 사본을 확인한 뒤 옮긴 프로젝트 폴더만 지운다
python3 "$M" --selftest
```

### 순서

1. **`plan`.** `<프로젝트>/.claude/manuals/.migrate-plan.json` 초안을 쓰고 표를 보여 준다.
   표의 칸: 원본 유무, 프로젝트 문구 줄 수, 전역에 이미 있는지, 다른 프로젝트에도 있는지.
   전역에 같은 ID·별칭·sha256이 있으면 `pointer`, 나머지는 모두 `review`로 시작한다.
2. **분류 (메인이 판단, 사용자 확인).** 계획 파일의 `action`을 정한다.

   | action | 언제 |
   |---|---|
   | `migrate` | 부품 데이터시트·RM·앱노트·정오표 |
   | `pointer` | 전역에 이미 있다. `target`에 전역 ID를 적는다 (예: 프로젝트 `stm32g431`이 전역 `stm32g431rb`를 가리킴) |
   | `keep` | 센서·장비 매뉴얼, 보드 회로도, 평가보드, 프로젝트 문서 |

   `aliases`에 품번 기본형을 적는다 (`stm32c071rb`면 `stm32c071`). **ID는 바꾸지 않는다** — 프로젝트 문서가 그 ID를 가리킬 수 있다.
   다른 프로젝트에 같은 부품이 있으면 Rev가 새롭거나 내용이 많은 쪽을 먼저 `migrate`하고, 나머지 프로젝트는 나중에 `pointer`로 처리한다.
   `review`가 하나라도 남아 있으면 `apply`가 거부한다. 분류 표를 사용자에게 보여 주고 확인을 받은 뒤 다음으로 간다.
3. **`apply`.** `migrate` 항목마다:
   - 폴더를 `~/.claude/manuals/<id>/`로 복사한다. 같은 ID 폴더가 이미 있으면 건너뛰고 `pointer`로 바꾸라고 알린다
   - 원본이 있으면 `source.pdf`로 복사한다. **없으면 다이제스트만 옮기고** `source: null`, `source_missing: true`로 둔다.
     원본 페이지 조회는 PDF를 다시 구해 `--component --update <id> <pdf>`를 할 때까지 안 된다
   - `metadata.json`: `scope: global`, `kind: component`, `origin`, `aliases`, `migrated_from`, `migrated_at`, `kicad`
   - `digest.md` 프론트매터의 `scope`·`source`를 고치고 `kind`·`aliases`·`origin`을 더한다. 본문은 건드리지 않는다
   - KiCad 위치: ID·별칭을 대문자 심볼 이름으로 찾는다(`--project`로 프로젝트 라이브러리 표까지 본다). 못 찾으면 `null`
   - 전역 INDEX.md 표 끝에 `[부품]` 줄을 더하고, 프로젝트 INDEX.md의 그 줄은 `[전역]` 제목 + 전역 digest 링크로 바꾼다

   `pointer` 항목은 전역 메타데이터의 `aliases`에 프로젝트 ID를 더하고 프로젝트 INDEX 줄만 바꾼다.
4. **프로젝트 문구 정리 (메인).** `apply` 출력의 "프로젝트 문구 N줄"을 전역 `digest.md`에서 고친다(5절 규칙).
   지운 내용 중 남길 것은 프로젝트 INDEX.md의 `[전역]` 줄 제목 칸 끝에 `— 본 보드 QSOP-16`처럼 붙인다.
   분할본이 있는 항목은 `split_md.py update`를 이어서 실행한다.
5. **`cleanup` (사용자 확인 후).** 전역에 `digest.md`와 `metadata.json`이 있는 항목만 프로젝트 폴더를 지운다.
   지우기 전에 지울 목록을 보여 주고 확인을 받는다. 되돌릴 수 없는 단계라 `apply`와 나눴다.

### 확인

- `ls ~/.claude/manuals/<id>/`에 `digest.md`·`metadata.json`(원본이 있었으면 `source.pdf`)이 있다.
- 프로젝트 INDEX.md의 그 줄 제목이 `[전역]`으로 시작하고 링크가 전역 digest를 가리킨다.
- 같은 프로젝트에 `plan`을 다시 돌리면 옮긴 항목이 모두 `pointer`로 나온다.
