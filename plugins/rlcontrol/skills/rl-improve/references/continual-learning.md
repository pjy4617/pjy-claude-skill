# 운영 데이터 기반 지속 개선(Continual Learning) 가이드

배포된 RL 정책을 운영 중 쌓이는 데이터로 개선하는 **관리된 루프**의 참조 문서.
핵심 전제: **학습은 오프라인(로그/시뮬)에서, 실기에는 검증된 정책만 교체 배포한다.**
라이브러리 버전별 세부 API(d3rlpy 클래스·SB3 재학습 인자 등)는 단정하지 말고
context7 MCP(`mcp__plugin_context7_context7__*`) 또는 공식 문서로 확인한다.

## 1. 데이터 플라이휠 — 왜 "관리된 루프"인가

운영 데이터는 RL의 가장 큰 자산이다: 배포 정책이 실기에서 만드는 데이터는 시뮬레이터가
놓치는 실제 동역학(마모·온도·부하 변동)을 담고 있고, 이것으로 재학습하면 성능이 오른다.
그러나 **배포 정책을 실장비에서 그대로 온라인 학습하는 것은 금지**한다:

- **탐색 위험** — 온라인 RL은 차선/무작위 행동을 시도해야 학습된다. 실장비에서는 사고·파손 직결.
- **파국적 망각(catastrophic forgetting)·정책 붕괴** — 새 데이터에 적응하다 기존 능력을 잃거나 발산.
- **검증 불가** — 학습이 즉시 생산 동작에 반영되면 회귀를 사후에야 발견한다.
- **자기 편향** — 정책이 자기 행동으로 데이터 분포를 결정 → 커버리지가 좁아지고 편향 누적.

따라서 루프는 항상: **수집 → (오프라인) 재학습 → 재검증 → 가드형 재배포** 순서다.

## 2. 운영 로그 수집 설계 (CRITICAL — 루프의 성패를 좌우)

재학습에는 전이 `(s, a, r, s')`가 재구성 가능해야 한다. 배포 시점부터 다음을 로깅한다:

| 항목 | 이유 |
|------|------|
| **정규화 전 원시 관측** | 정규화 통계는 재학습 때 바뀔 수 있다 — 원시값이 정본 |
| **정책 원출력 + 안전 계층 통과 후 실제 인가 행동** | 학습 대상은 "무엇이 인가됐나". 클리핑/차단 빈도 자체가 진단 신호 |
| **보상 재계산에 필요한 신호** | 보상 함수를 나중에 고쳐도 로그에서 재계산 가능하게 (보상값만 저장하지 말 것) |
| 에피소드/운전 사이클 경계·타임스탬프 | terminated/truncated 구분·전이 연결에 필수 |
| 안전 이벤트·사람 개입 라벨 | 개입 구간은 정책 행동이 아님 — 학습에서 구분 처리 |
| 정책 버전·정규화 통계 버전 | 어떤 정책이 만든 데이터인지 추적(오프폴리시 보정·감사) |

실기 구동 프로그램이 C#/C++이면 로깅도 구동 프로그램 쪽에 구현한다
(`rl-implement`의 `references/cross-language-deployment.md`와 연결). 제어 주기보다 로깅이
느리면 링 버퍼+비동기 플러시로 제어 루프를 막지 않는다.

## 3. 경로 A — 오프라인 재학습 (기본 경로)

실기 탐색 없이 **로그만으로** 재학습한다. 실기를 건드리지 않으므로 안전하다.

- **알고리즘**: 오프라인 RL — CQL(Kumar et al. 2020)·IQL(Kostrikov et al. 2022)·
  TD3+BC(Fujimoto & Gu 2021), 구현은 d3rlpy(지원 알고리즘·API는 context7/문서 확인).
  일반 오프폴리시(SAC 등)를 로그에만 돌리면 OOD(분포 밖) 행동의 가치 과대추정으로 실패하기 쉽다 —
  데이터 분포에 정책을 붙들어두는 오프라인 전용 알고리즘을 쓴다.
- **데이터 커버리지 점검(선행 필수)**: 로그가 어떤 운전점·상태 영역을 덮는지 먼저 본다.
  배포 정책이 만든 로그는 그 정책의 궤적 주변에 편중된다 — 커버리지 밖 개선은 기대하지 말 것.
- **warm start**: 기존 정책 가중치에서 시작할지, 처음부터 학습할지 결정. warm start는 수렴이
  빠르지만 국소해에 갇힐 수 있다 — 두 방식 모두 학습해 재검증에서 비교하는 것이 안전.

## 4. 경로 B — offline-to-online 미세조정

오프라인 사전학습 후, **안전 계층·가드 하에서 제한적 온라인 상호작용**으로 미세조정한다.
안전 계층이 검증돼 있고 제한적 실기(또는 HIL) 상호작용이 허용될 때만.

- **알고리즘**: AWAC(Nair et al. 2020)·Cal-QL(Nakamoto et al. 2023)·IQL 온라인 미세조정 등
  offline-to-online 계열(구현·지원 여부는 context7/문서 확인).
- **함정 — 초기 성능 급락**: 온라인 전환 직후 분포 변화로 오프라인 성능이 일시 무너질 수 있다
  (offline-to-online 연구들이 다루는 핵심 문제). 낮은 학습률·보수적 탐색·오프라인 데이터 혼합
  리플레이로 완화하고, 급락 감지 시 즉시 폴백 제어기로 전환하는 가드를 둔다.
- 온라인 구간에도 **탐색은 안전 계층을 항상 통과**시킨다. 무제약 탐색 금지.

## 5. 경로 C — 시뮬레이터 재보정 (가장 안전)

sim-to-real 갭이 성능 한계의 주원인이면, 운영 데이터로 **시뮬레이터를 재보정**하고
개선된 시뮬에서 재학습한다. 실기를 전혀 건드리지 않는다.

- 운영 로그로 system identification: 시뮬 파라미터(마찰·관성·지연 등)를 실기 응답에 맞게 추정.
- 도메인 랜덤화 범위를 실측 분포 기준으로 갱신(과도하게 넓힌 랜덤화는 보수적 정책을 낳는다).
- 재보정 검증: 동일 입력 시퀀스에 대한 시뮬 vs 실기 응답 오차가 줄었는지 확인 후 재학습.

## 6. 파국적 망각·회귀 방지

- **이전 데이터 혼합**: 재학습 데이터에 이전 라운드 데이터·시뮬 데이터를 섞어 분포를 넓게 유지.
- **회귀 테스트 스위트**: 기존에 PASS한 시나리오 모음을 고정 스위트로 유지하고, challenger가
  전 항목을 다시 통과하는지 확인(성능 개선이 특정 운전점 희생으로 얻어진 것 아닌지).
- **정책 거리 모니터링**: 신규 정책이 champion과 얼마나 다른 행동을 내는지(동일 관측 배치에 대한
  행동 차이) 확인 — 급격한 변화는 재검증 강도를 높이는 신호.

## 7. 드리프트 모니터링·재학습 트리거

운영 중 다음을 상시 추적하고, 임계 초과 시 재학습을 트리거한다:

| 신호 | 예 |
|------|-----|
| 성능 지표 열화 | 추종 오차·정착 시간·오버슈트 추세 악화 |
| 안전 지표 | 제약 위반·안전 계층 개입(클리핑/차단) 빈도 증가 |
| 관측 분포 드리프트 | 운영 관측 분포가 학습 분포에서 이탈(통계 거리 추적) |
| 이벤트 | 정비·부품 교체·레시피 변경 등 동역학이 바뀌는 사건 |
| 주기 | 데이터 누적량·기간 기준 정기 재학습 |

트리거·임계는 설계서에 명시하고, "성능이 나쁘니 일단 재학습"이 아니라 **원인(드리프트인가,
커버리지 부족인가, sim-to-real 갭인가)에 맞는 경로(A/B/C)**를 고른다.

## 8. champion/challenger·shadow 평가

- **champion** = 현재 배포 정책(검증된 기준선). **challenger** = 재학습 정책.
- 평가 사다리(위험 낮은 순): ① 시뮬 다중 시드 비교(회귀 스위트 포함) → ② 로그 기반 오프폴리시
  평가(OPE — FQE 등. 참고 신호일 뿐 **과신 금지**: OPE 추정은 분산·편향이 크다) →
  ③ **shadow 배포**(실기에서 challenger는 추론만 수행, 명령은 champion이 인가 — 행동 차이·지연 관찰) →
  ④ 제한 구간 가드 운전 → ⑤ 승격.
- champion은 승격 후에도 **보존**한다(즉시 롤백 경로). 두 정책의 버전·학습 데이터 스냅샷·시드를 기록.

## 9. 재배포 거버넌스

- **재학습 정책도 신규 정책과 동일하게 `rl-test`의 실기 전환 가드 게이트 10항목을 재통과**해야
  재배포할 수 있다. 예외 없음("작은 업데이트라서 생략" 금지).
- 사람 승인 절차·재배포 창(생산 영향 최소 시점)·롤백 절차(champion 복귀 조건·방법)를 문서화.
- C#/C++ 구동 프로그램 배포면 ONNX 재export 후 **패리티 테스트**(Python vs 구동 프로그램 추론
  일치)와 정규화 통계 버전 일치 확인을 반복한다(`cross-language-deployment.md` §8).
- 기록(재현성): 정책 버전 ↔ 학습 데이터 범위 ↔ 하이퍼파라미터 ↔ 시드 ↔ 게이트 결과를 남긴다.

## 10. 체크리스트 (루프 1회전)

- [ ] 로그에서 `(s, a, r, s')` 재구성 가능(원시 관측·인가 행동·보상 신호·경계) 확인
- [ ] 재학습 트리거·원인 진단(드리프트/커버리지/sim-to-real) 기록
- [ ] 경로 A/B/C 선택 근거 기록 (B면 안전 계층 하 제한 상호작용 계획 포함)
- [ ] 데이터 커버리지 점검·이전 데이터 혼합(망각 방지)
- [ ] challenger vs champion 다중 시드 비교 + 회귀 스위트 전 항목 PASS
- [ ] 실기 전환 가드 게이트 10항목 재통과 (rl-test)
- [ ] (해당 시) shadow 평가 → 제한 구간 가드 운전 → 사람 승인 → 승격
