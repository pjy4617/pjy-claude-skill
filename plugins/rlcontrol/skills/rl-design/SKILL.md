# 강화학습 알고리즘 검토 및 환경/보상/안전 설계

> 이 스킬은 제어 문제에 적용할 **RL 알고리즘을 선정**하고 **환경·보상·안전 계층을 설계**합니다.
> 실제 설계 작업은 **rlctrl-algorithm-designer 에이전트**에게 위임합니다.
> `references/` 3개 문서(알고리즘 카탈로그·알고리즘 선정 로직·보상/안전 설계)를 참조합니다.

**전제**: 이 스킬은 `rl-assess`가 **Go 판정**한 문제 규격(문제 정의·MDP 초안·안전 요구)을 입력으로 받는 것이
표준 흐름입니다. rl-assess를 거치지 않은 직접 요청이면, 설계에 앞서 **적용 가능성이 이미 검토되었는지**를
먼저 확인하고, 미검토라면 `rl-assess`(rlctrl-feasibility-analyst) 선행을 권합니다 —
RL이 부적합한 문제에 알고리즘을 붙이는 것은 이 플러그인이 가장 경계하는 일입니다.

**안전 원칙 상기**: 설계 단계에서부터 무제약·무보호 정책을 실기에 직배포하지 않는다는 전제를 지킵니다.
안전 계층(action clipping·shielding)·폴백 고전 제어기·시뮬레이터 우선 검증을 설계에 **반드시 포함**합니다.

## 입력

- rl-assess의 적용 가능성 리포트(문제 규격·MDP 초안·리스크·권장 경로) — 있으면 그대로 사용
- 없으면 다음을 확인(부족하면 질문으로 수집):
  - 제어 대상·목표(추종/정치/에너지 최소화/택트 최소화 등)
  - **행동공간**: 연속(토크/전압/속도 지령) / 이산(모드 전환·게인 셋 선택) / 혼합
  - **관측 신호**: 센서 목록·노이즈·지연·부분 관측(POMDP) 여부
  - **샘플 예산**: 시뮬레이터로 무제한 상호작용 가능 / 실기 상호작용만 가능 / 과거 로그만 존재(오프라인)
  - **안전 요구**: 안전 한계(위치·속도·토크·온도), 위반의 결과(장비 손상·인명), 폴백 제어기 유무
  - 사이클타임·실시간 추론 지연 예산

## 설계 절차 (6단계)

1. **문제 특성 확인** — 행동공간(연속/이산/혼합)·샘플 예산(온라인/오프라인)·온라인 상호작용 가능 여부·
   부분 관측성·안전 제약 강도를 표로 정리한다. 이 5개 축이 알고리즘 선정의 결정 변수다
   (`references/algorithm-selection.md`의 결정 변수 5개와 동일).
2. **알고리즘 검토·선정** — `references/algorithm-catalog.md`의 계열별 특성표(행동공간·온/오프폴리시·
   샘플효율·안정성·하이퍼파라미터 감도·대표 라이브러리·출처)를 훑고,
   `references/algorithm-selection.md`의 **문제 특성 → 알고리즘 결정표**로 후보를 좁힌다.
   실무 기본값(연속 첫 시도 = SAC 또는 PPO, 이산 = PPO 또는 DQN 계열, 실기 데이터만·탐색 불가 =
   오프라인 RL, 안전 제약 강함 = Safe RL/shielding)을 출발점으로 하되 **근거와 함께** 확정한다.
3. **환경 설계 개요** — 관측/행동 공간 정의와 **스케일·정규화**(관측 표준화·행동 [-1,1] 매핑),
   에피소드 경계(terminated vs truncated), 초기 상태 분포, 도메인 랜덤화 계획을 정한다.
   구현 상세는 `rl-implement`로 넘기고 여기서는 규격만 확정한다.
4. **보상 설계** — `references/reward-and-safety.md`에 따라 조밀/희소 선택·shaping(가능하면
   potential-based로 최적 정책 불변성 유지)·**reward hacking 방지**·다목적 가중 또는 제약화를 설계한다.
   보상 함수 초안을 수식/의사코드로 명시한다.
5. **안전 설계** — 제약 MDP 정식화(비용 함수·제약 한계)·Lagrangian 또는 안전 계층(action clipping·
   shielding)·**폴백 고전 제어기 상시 대기**·Sim2Real 안전 마진을 아키텍처로 설계한다.
   "안전은 보상 항으로만 두지 않는다"(위반이 치명적이면 하드 제약/shielding)를 원칙으로 한다.
6. **설계 문서 산출** — 아래 산출물 형식의 마크다운 문서를 작성한다.

## 산출물: 설계 문서 형식

```markdown
# {제어 대상} RL 설계서

## 1. 문제 특성 요약        ← 행동공간 | 샘플예산(온/오프라인) | 온라인 상호작용 가능 여부 | 관측성 | 안전제약 강도
## 2. 알고리즘 선정         ← 선정 알고리즘 + 후보 비교표 + 선정 근거(왜 이 기본값인지), 대표 라이브러리
## 3. 환경 규격            ← 관측공간(정규화 방식) | 행동공간(스케일/클리핑) | 에피소드 경계 | 초기분포 | 도메인 랜덤화
## 4. 보상 함수            ← 항별 정의(수식/의사코드) | 조밀/희소 | shaping 방식 | reward hacking 대비 | 다목적/제약 처리
## 5. 안전 아키텍처         ← 안전 한계표 | 제약 처리(제약 MDP/Lagrangian/shielding/clipping) | 폴백 제어기 | Sim2Real 마진
## 6. 하이퍼파라미터 시작점  ← 알고리즘별 초기값(학습률·버퍼/롤아웃·감가율·엔트로피 등) + 튜닝 우선순위
## 7. 리스크와 미결 사항     ← 항목별 심각도(CRITICAL/MAJOR/MINOR/INFO)와 완화책
```

리스크 심각도는 레포 관례에 따라 **CRITICAL / MAJOR / MINOR / INFO** 4등급으로 표기합니다.
하이퍼파라미터 값은 **시작점**이며 라이브러리 버전별 기본값·인자명은 단정하지 말고
context7 MCP(`mcp__plugin_context7_context7__*`) 또는 공식 문서로 확인하도록 문서에 명시합니다.

## rlctrl-algorithm-designer 에이전트 위임

실제 설계 작업은 `rlctrl-algorithm-designer` 에이전트에게 위임합니다. 에이전트에게 전달할 정보:

- rl-assess의 적용 가능성 리포트(있으면) 또는 수집된 문제 특성 표
- 제어 대상·목표·안전 요구, 관측/행동 신호 목록
- 기존 시뮬레이터/환경/코드베이스가 있으면 그 경로
- 설계 문서 출력 경로(기본: 프로젝트 루트 `docs/` 또는 사용자 지정)
- **references 정본 절대 경로**: `${CLAUDE_SKILL_DIR}/references/` 아래 문서들
  (`algorithm-catalog.md` / `algorithm-selection.md` / `reward-and-safety.md`)
  — 호출 시 실제 절대 경로로 치환하여 전달합니다. 에이전트는 `.claude/agents/`로 단독 설치되어
  상대 references 경로가 깨지므로, 위임 프롬프트에 정본 절대 경로를 넘기는 것이 표준입니다.

## 라이브러리 버전 확인 원칙

알고리즘 특성·수식·출처는 확립된 사실만 기술합니다. 반면 **라이브러리(Stable-Baselines3·SB3-Contrib·
CleanRL·d3rlpy·omnisafe 등)의 버전별 클래스명·인자명·기본 하이퍼파라미터는 단정하지 않고**
context7 MCP 또는 공식 문서로 확인하도록 설계 문서에 확인 지시를 남깁니다.
