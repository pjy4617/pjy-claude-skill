# 알고리즘 선정 로직 (문제 특성 → 알고리즘)

`algorithm-catalog.md`의 후보 중에서 **문제 특성으로 알고리즘을 좁히는** 결정 규칙이다.
핵심 결정 변수는 5개: **①행동공간(연속/이산/혼합) ②샘플 예산(온라인 무제한 vs 실기 제한) ③온라인 상호작용 가능 여부
④안전 제약 강도 ⑤부분 관측성(POMDP)**. 이 5개가 정해지면 후보는 대부분 1~2개로 압축된다.

## 1. 선정 플로차트

```text
[시작] 학습 시점에 환경과 새로 상호작용할 수 있는가?
├─ 아니오 (과거 로그만 존재, 온라인 탐색 불가/위험)
│      └─→ 오프라인 RL:  CQL / IQL / TD3+BC (연속)  ·  CQL/IQL (이산)
│           · 데이터 커버리지 좋음 → TD3+BC(단순) 먼저
│           · 분포 이탈 우려 큼   → CQL(보수적) 또는 IQL(안정)
│           ※ 배포 전 반드시 별도 안전 검증(오프라인 성능 ≠ 실기 성능)
│
└─ 예 (시뮬레이터 또는 가드된 실기 상호작용 가능)
       │
       ├─ 안전 제약이 강한가? (위반 = 장비손상/인명, 비용 함수로 명시 필요)
       │      └─ 예 → Safe RL:  PPO-Lagrangian / CPO(온폴리시) · SAC-Lagrangian(연속·오프폴리시)
       │              + 런타임 shielding / action clipping / 폴백 제어기 (하드 안전 계층 병행 필수)
       │
       └─ 안전 제약이 보통 (안전은 clipping/폴백으로 처리, 학습은 성능 위주)
              │
              ├─ 행동공간이 이산인가? (모드 선택·게인 셋·on/off)
              │      └─ 예 → PPO (기본)  또는  DQN 계열(QR-DQN/Dueling/Double)
              │              · 샘플효율이 중요하고 이산 → DQN 계열(리플레이)
              │              · 견고함/튜닝 관대 우선   → PPO
              │
              └─ 연속 행동 (토크/전압/속도 지령)
                     │
                     ├─ 샘플이 비싼가? (실기 상호작용 위주, 상호작용 예산 빠듯)
                     │      └─ 예 → SAC (1순위) / TD3
                     │              · 극도로 샘플 빈곤 + 동역학 학습 가능 → 모델기반(MBPO/PETS/Dreamer) 검토
                     │
                     └─ 시뮬레이터로 대량 상호작용 가능 (샘플 저렴)
                            └─→ PPO (견고한 기본)  또는  SAC (샘플효율 원하면)
```

## 2. 문제 특성 → 알고리즘 결정표

| 행동공간 | 샘플 예산 | 온라인 상호작용 | 안전 제약 | 1순위 | 대안 | 근거 |
|---------|----------|----------------|----------|-------|------|------|
| 연속 | 저렴(시뮬레이터) | 가능 | 보통 | **PPO** | SAC | 튜닝 관대·견고, 대량 롤아웃에 강함 |
| 연속 | 비쌈(실기) | 가능 | 보통 | **SAC** | TD3 | 리플레이로 샘플 재사용, 안정·자동 온도 |
| 연속 | 극빈 | 가능 | 보통 | **모델기반(MBPO/PETS)** | SAC | 최고 샘플효율(단 튜닝 난도↑) |
| 연속 | — | 가능 | 강함 | **SAC-Lagrangian / PPO-Lag** | CPO | 비용 제약 명시 + shielding/폴백 |
| 이산 | 저렴 | 가능 | 보통 | **PPO** | QR-DQN | 이산에 견고 |
| 이산 | 비쌈 | 가능 | 보통 | **DQN 계열** | PPO | 리플레이로 샘플효율↑ |
| 이산 | — | 가능 | 강함 | **CPO / PPO-Lag** | + shielding | 온폴리시 제약 최적화(이산은 이 행, 연속은 위 행) |
| 이산/연속 | 고정 데이터 | **불가** | (전제) | **CQL / IQL / TD3+BC** | BCQ | 오프라인 RL |

> "샘플이 비싸다" 판단 기준: 1스텝 상호작용에 실기 시간/마모/리스크가 드는가. 시뮬레이터가 충실하고 병렬화 가능하면 저렴으로 본다.

## 3. 실무 기본값 지침 (그리고 왜)

RL을 제어에 처음 붙일 때 아래 기본값에서 출발하고, 문제 특성이 명확히 다르면 표로 조정한다.

### (a) 연속 제어 첫 시도 = SAC 또는 PPO
- **SAC**: 오프폴리시라 리플레이 버퍼로 샘플을 재사용 → 실기처럼 상호작용이 비쌀 때 유리. 엔트로피 정규화·자동 온도 조정으로 하이퍼파라미터에 비교적 관대하고 안정적(Haarnoja et al. 2018).
- **PPO**: 온폴리시라 샘플효율은 낮지만 **클리핑 목적함수로 매우 견고**하고 튜닝이 관대(Schulman et al. 2017). 시뮬레이터로 대량·병렬 롤아웃이 가능하면 낮은 샘플효율이 문제되지 않는다.
- 판단: **시뮬레이터 대량 상호작용 가능 → PPO**, **실기/샘플 비쌈 → SAC**. 둘 다 널리 검증된 견고한 출발점이며, DDPG는 불안정성 때문에 신규 첫 선택으로 비권장.

### (b) 이산 제어 = PPO 또는 DQN 계열
- **PPO**: 이산 행동에서도 그대로 견고하게 동작. 알고리즘을 하나로 통일하고 싶을 때.
- **DQN 계열(Double/Dueling/QR-DQN)**: 오프폴리시 리플레이로 **샘플효율**이 필요할 때. 순수 DQN보다 Double(과대추정 완화)·Dueling·QR-DQN 조합을 권장.
- 판단: **견고·통일 → PPO**, **이산 + 샘플효율 중요 → DQN 계열**.

### (c) 실기 데이터만 있고 온라인 탐색 불가 = 오프라인 RL
- 온라인 탐색이 안전상 불가하거나 데이터가 이미 쌓여 있으면 **CQL/IQL/TD3+BC**. 환경 상호작용 없이 학습하되, **분포 이탈**로 인한 과대추정을 억제하는 것이 이 계열의 핵심.
- 판단: 데이터 커버리지 좋음 → **TD3+BC**(단순·안정), 분포 이탈 우려 큼 → **CQL**(보수적) 또는 **IQL**(정책 밖 Q 미조회로 안정). **오프라인 성능은 실기 성능을 보장하지 않으므로** 배포 전 별도 검증 게이트를 둔다.

### (d) 안전 제약이 강함 = Safe RL + 하드 안전 계층
- 위반이 곧 손상/위험인 문제는 제약 MDP로 정식화하고 **PPO-Lagrangian/CPO/SAC-Lagrangian**으로 비용 제약을 명시적으로 다룬다.
- 단, Lagrangian 소프트 제약은 "평균적" 만족이지 매 스텝 하드 보장이 아니다. 따라서 **런타임 shielding·action clipping·폴백 고전 제어기**를 항상 병행한다(`reward-and-safety.md`). 판단: 학습형 제약 + 하드 안전 계층은 택일이 아니라 **동시** 적용.

## 4. 흔한 함정 (선정 단계에서 미리 차단)

| 함정 | 증상 | 대응 |
|------|------|------|
| 연속 제어를 DQN으로 | 행동 이산화로 성능 상한↓·차원의 저주 | 연속 계열(SAC/TD3/PPO) 사용 |
| 첫 시도부터 DDPG | 발산·재현 안 됨 | TD3/SAC로 대체(DDPG의 개선판) |
| 실기 탐색이 위험한데 온라인 온폴리시 | 학습 중 안전 위반·장비 손상 | 오프라인 RL 또는 시뮬레이터 선행 + shielding |
| 안전을 보상 벌점 하나로만 | 벌점 회피가 곧 보상 해킹, 위반 잔존 | 제약화(Lagrangian) + 하드 shielding/폴백 |
| 모델기반을 생산 기본값으로 | 모델 편향·튜닝 난도로 좌초 | 샘플이 정말 극빈일 때만, 아니면 SAC/PPO 먼저 |
| POMDP를 MDP로 취급 | 부분 관측으로 학습 불안정 | 프레임 스택·순환정책(RecurrentPPO 등)·상태 추정 |

## 5. 선정 결과 문서화 체크

- [ ] 5개 결정 변수(행동공간·샘플예산·온라인 상호작용·안전강도·관측성)를 표로 명시했는가
- [ ] 1순위 알고리즘 + 대안 1개, **각 선정 근거**를 적었는가
- [ ] 대표 라이브러리(예: SB3 `SAC`, SB3-Contrib `TQC`/`QR-DQN`, d3rlpy, omnisafe)를 후보로 지목했는가 — 단, 클래스명·인자명·버전 기본값은 context7/공식 문서 확인 지시로 남긴다
- [ ] 안전 제약이 있으면 학습형 제약 + 하드 안전 계층 병행을 명시했는가
- [ ] 첫 시도 기본값(SAC/PPO 등)에서 벗어났다면 그 이유를 근거로 남겼는가
