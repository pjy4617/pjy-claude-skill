# 강화학습(RL) 정책 성능·기능·안전 테스트

> 이 스킬은 학습이 끝난 **RL 정책(policy)**을 장비 제어 실무 기준으로 평가·검증한다.
> 실제 평가 스크립트 작성·실행·통계 분석·판정은 **rlctrl-evaluator 에이전트**에게 위임한다.
> 성능 통계 프로토콜은 `references/evaluation-protocol.md`, 기능·안전·실기 전환 검증은 `references/functional-safety-tests.md`를 참조한다.
>
> **페르소나**: 강화학습을 20년 이상 실제 장비 제어 프로젝트에 상용으로 적용해 온 전문가. 성능·안정성을 최적화하되, **무엇보다 "이 정책이 실기에 안전한가"를 냉정하게 판정한다.**

## 핵심 원칙

- **높은 평균 리턴 ≠ 안전.** 장비 제어에서 정책은 성능뿐 아니라 제약 준수·안정성·강건성·워스트케이스 거동으로 판정한다.
- **RL 성능 수치는 고분산·재현성 취약.** 단일 실행·최고 실행(cherry-pick) 보고는 신뢰할 수 없다 — 다중 시드·신뢰구간이 필수다(근거: Henderson et al. 2018, "Deep Reinforcement Learning that Matters"; Agarwal et al. 2021, rliable).
- **시뮬 성능 = 실기 성능이 아니다(sim-to-real gap).** 시뮬 전 항목 PASS는 실기 안전을 보장하지 않는다 — 실기 전환은 가드 게이트를 통과해야 한다.
- **무제약/무보호 정책을 실기에 직배포하지 않는다** — 안전 계층(action clipping·shielding)·폴백 고전 제어기·비상 정지·사람 감독 하 가드형 전환을 항상 전제.
- 라이브러리(rliable/SB3 등) API·버전 세부는 단정하지 말고 **context7 MCP(`mcp__plugin_context7_context7__*`) 또는 공식 문서로 확인**한다(추측 금지). Gymnasium 환경은 **5-튜플** API(`step` → `(obs, reward, terminated, truncated, info)`)를 전제.

## 평가 절차 (5단계)

1. **평가 대상·기준 결정** — 무엇을(체크포인트/최종 정책), 어느 수준에서(시뮬레이터 / HIL / 실기), 어떤 판정 기준(성능 목표·안전 제약·실무 사양)으로 검증할지 확정. 부족하면 인터뷰로 수집.
2. **성능 평가** — 다중 시드(최소 5, 실기 후보 10)·평균±신뢰구간·IQM/부트스트랩 학습곡선·점근 성능 vs 샘플 효율 구분·베이스라인 대비·deterministic 평가 (`references/evaluation-protocol.md`).
3. **기능·안전 테스트** — 제약 위반율·정상상태 안정성·외란/파라미터 강건성·sim-to-real 검증·워스트케이스/적대적 외란·엣지 케이스·비상 정지 동작 (`references/functional-safety-tests.md`).
4. **통계적 유의성 판정** — RL 고분산 함정에 주의해 점 추정 단독 판정 금지. 신뢰구간·IQM으로 결론, 시드 부족(<5)이면 "예비 결과"로 유보.
5. **리포트** — 성능·기능·안전 종합 PASS/FAIL, 발견 이슈 심각도 등급화(CRITICAL/MAJOR/MINOR/INFO), 재현 조건(시드·시드당 에피소드·환경 설정) 명시.

## 평가 수준

| 수준 | 대상 | 실행 환경 | 비고 |
|------|------|-----------|------|
| 시뮬레이터 | 정책의 지령 레벨 성능·로직·안전 계층 | Gymnasium 환경(시뮬레이터/모델) | 성능·강건성·워스트케이스의 1차 검증 |
| HIL / 축소 실기 | 실 인터페이스·지연·일부 물리 | Hardware-in-the-loop 또는 저충실도 축소 장비 | 안전 계층·폴백 상시 |
| 실기 인수 | 실 액추에이터·센서·안전 계통 | 실 장비 | **실기 전환 가드 게이트 선행 필수**, 사람 감독·저속 시운전 |

## 통계 원칙 (요약 — 상세는 evaluation-protocol.md)

- **다중 시드 ≥5**(실기 후보 ≥10), 학습 시드와 평가 시드 **분리**.
- 점 추정만 보고 금지 — **평균±95% 신뢰구간** 또는 **IQM + 층화 부트스트랩 CI**(소수 시드에 강건, rliable 관점).
- **학습곡선(동일 예산·시드 밴드) + 점근 성능 + 샘플 효율**을 분리 보고.
- **평가는 deterministic 정책**(예: SB3 `predict(obs, deterministic=True)` — 시그니처는 context7 확인). 환경 확률성은 다중 에피소드 평균으로 흡수.
- 최고 실행 cherry-pick 금지, 실패 시드 포함 보고.

## 베이스라인 대비 (반드시)

성능 수치는 절대값이 아니라 베이스라인 대비로 해석한다 — 동일 환경·동일 평가 프로토콜로 측정한다.

| 베이스라인 | 목적 |
|-----------|------|
| 랜덤 정책 | 하한 — 학습이 실제로 일어났는지 |
| 무학습/초기 정책 | 개선량 측정 기준 |
| 고전 제어기(PID/LQR/MPC) | 실무 대안 — 못 이기면 RL 도입 근거 약함(→ `rl-assess` 게이트로 회귀) |
| 기존 배포 정책/컨트롤러 | 회귀 방지 — 현행보다 나은가 |

## 기능·안전 테스트 카탈로그 (요약 — 상세는 functional-safety-tests.md)

| 항목 | 방법 | 판정 |
|------|------|------|
| 제약 위반율 | 평가 롤아웃 전체에서 안전 한계(위치/속도/토크 등) 초과 스텝·에피소드 빈도 | 안전-크리티컬 제약은 **위반율 0** 목표 |
| 정상상태 안정성 | 장시간 롤아웃의 정상상태 오차·진동·액션 채터링 | 발산·리밋사이클·과도 채터링 없음 |
| 외란 강건성 | 부하/노이즈/지연/결측을 크기 스윕 주입 → 성능·위반율 곡선 | 규정 외란 범위 내 안전 유지 |
| 파라미터/모델 불확실성 | 도메인 랜덤화 분포 내·외 파라미터 평가 | 실기 파라미터가 학습 분포 내, 급락 경계 식별 |
| sim-to-real 검증 | 시뮬 PASS → HIL/축소 → 감독 하 저속 실기 → 점진 확대 | 각 단계 성능·안전 지표 갭 정량화 |
| 워스트케이스/적대적 | 최악 초기조건·외란·파라미터 조합 탐색 | 워스트케이스에서도 제약 유지 |
| 엣지 케이스 | 액션 포화·OOD 관측·센서 결측/스파이크·통신 드롭 | 안전 계층이 방어 |
| 비상 정지·폴백 | 안전 계층 차단·폴백 전환·NaN/지연 초과 시 안전 수렴 | 주입 테스트 통과 |

## 장비 제어 실무 판정 기준

RL 정책도 고전 제어 사양서와 **같은 잣대**로 판정해야 실무 수용된다.

| 지표 | 정의 | 판정 예 |
|------|------|---------|
| 허용 오차(정상상태 오차) | 목표 대비 정착 후 잔류 오차 | 허용 밴드(±ε) 내 |
| 정착 시간(settling time) | 허용 밴드 진입·유지까지 시간 | 사양 이하 |
| 오버슈트(overshoot) | 목표 초과 최대치 | 사양 % 이하 |
| 안전 마진 | 위치/토크/속도 한계까지 여유 | 규정 마진 확보 |

## 실기 전환 가드 게이트

시뮬 전 항목 PASS 후에도 실기 투입 전 아래를 명시 확인한다. **하나라도 미충족이면 실기 배포 [CRITICAL] 보류** (상세는 `references/functional-safety-tests.md` §11).

1. **안전 계층 활성** — action clipping/shielding 활성·주입 테스트 통과
2. **폴백 상시 대기** — 폴백 고전 제어기 전환 동작 확인(정책 실패·NaN·지연 초과 시)
3. **비상 정지 경로 검증**
4. **제약 위반율 0** — 워스트케이스 포함
5. **파라미터 분포 확인** — 실기 파라미터가 학습/랜덤화 분포 내
6. **추론 지연 예산 충족** — deterministic 정책, 지연 초과 시 폴백
7. **감독 시운전 계획** — 사람 감독 하 저속·소범위
8. **로깅·롤백 계획** — 실기 데이터 로깅, 실패 시 롤백
9. **성능 근거** — `evaluation-protocol.md` 기준(다중 시드·베이스라인) 충족

## rlctrl-evaluator 에이전트 위임

이 스킬은 실제 작업을 `rlctrl-evaluator` 에이전트에게 위임한다. 에이전트에게 전달할 정보:

- 평가 대상 정책/체크포인트 경로, 학습에 쓴 알고리즘(예: SAC/PPO)·프레임워크(SB3 등)
- 평가 환경(Gymnasium 환경 코드·시뮬레이터/실기 여부, 관측/행동 공간, 안전 제약)
- 평가 수준(시뮬레이터 / HIL / 실기 전 게이트)과 판정 기준(성능 목표·안전 제약·실무 사양치)
- 베이스라인(고전 제어기·기존 정책) 유무 및 경로
- **references 정본 절대 경로**: `${CLAUDE_SKILL_DIR}/references/` 아래 문서들(`evaluation-protocol.md`, `functional-safety-tests.md`) — 호출 시 실제 절대 경로로 치환하여 전달(에이전트는 `.claude/agents/`로 단독 설치되어 상대 references 경로가 깨지기 때문)

## 크로스 플러그인

장비가 WMX3 모션 제어 기반이면 `wmx3app`의 SimuPlatform을 Gymnasium 평가 환경으로 감싸 사용하고, 실기 전환은 `wmx3app`의 `wmx3-app-test` 실기(EtherCAT) 전환 체크리스트를 이 게이트와 병행할 수 있다.
