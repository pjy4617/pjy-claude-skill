# RL 정책 기능·안전 테스트

> **원칙**: 높은 평균 리턴은 **안전을 보장하지 않는다**. 장비 제어에서 정책은 성능뿐 아니라 제약 준수·안정성·강건성·워스트케이스 거동으로 판정한다. 무제약/무보호 정책을 실기에 직배포하지 않는다 — 안전 계층(action clipping·shielding)·폴백 고전 제어기·비상 정지를 전제한다.
> 성능 통계 프로토콜은 `evaluation-protocol.md`를 참조한다. 이 문서는 그 위에 얹는 기능·안전 검증과 실기 전환 게이트를 다룬다. 심각도 표기는 CRITICAL / MAJOR / MINOR / INFO.

## 1. 제약 위반율 (constraint violation rate)

- 안전 한계(위치·속도·토크·온도·힘 등)를 초과하는 스텝·에피소드 빈도.
- 측정: 평가 롤아웃 전체에서 `위반 스텝 / 전체 스텝`, `위반 에피소드 / 전체 에피소드`.
- 판정: 안전-크리티컬 제약은 **위반율 0을 목표**로 한다. 0이 아니면 안전 계층(shielding) 없이는 배포 불가([CRITICAL]).
- Safe RL(제약 MDP·Lagrangian)로 학습했더라도 **학습 중 위반 ≠ 배포 시 위반** — 배포용 deterministic 정책에서 재측정한다.
- 워스트케이스(§7) 조건 하 위반율을 별도로 보고한다.

## 2. 정상상태 안정성 (steady-state stability)

- 목표 도달 후 정착 상태에서 발산·리밋사이클·채터링(chattering) 없이 유지되는가.
- 측정: 장시간 롤아웃에서 정상상태 오차·진동 진폭·제어 입력 채터링(액션 변화율).
- RL 정책은 보상만 최적화하면 물리적으로 거친 제어(액션 급변)를 낼 수 있다 — **액션 평활도(action smoothness)** 지표와 정착 후 유지를 함께 확인한다(필요 시 보상에 액션 변화 페널티를 두었는지 `rl-design` 보상 설계와 대조).

## 3. 외란 주입 강건성 (disturbance robustness)

- 외란(부하 토크, 센서 노이즈, 액추에이터 지연, 관측 결측 등)을 주입해 성능·안전 저하를 측정한다.
- 방법: 외란 크기를 스윕(계단·램프·임펄스·지속 노이즈)하며 성능/제약 위반율 곡선을 그려 **강건 한계**(어느 외란까지 안전한가)를 도출한다.
- 관측 노이즈·액추에이터 지연·신호 양자화도 포함한다.

## 4. 파라미터/모델 불확실성 (도메인 랜덤화 검증)

- 학습 시 도메인 랜덤화(질량·마찰·지연·게인 등 파라미터 분포)를 썼다면, **분포 내(interpolation) + 분포 밖(extrapolation)** 파라미터에서 평가한다.
- 실 장비 파라미터가 학습 분포에 포함되는지 확인한다 — 분포 밖이면 sim-to-real 갭 위험([MAJOR] 이상).
- 파라미터 스윕으로 성능/안전이 급락하는 경계(취약점)를 식별해 보고한다.

## 5. sim-to-real 검증 절차

- **시뮬 성능 = 실기 성능이 아니다(sim-to-real gap).** 시뮬 지표·물리 미모델링(마찰·백래시·지연·노이즈)이 갭의 원인이다.
- 절차(단계별 게이트, 각 단계 안전 계층·폴백 상시):
  1. 시뮬 전 항목(§1~§4, §7~§9) PASS
  2. HIL(hardware-in-the-loop) 또는 저충실도 축소 실기 시험
  3. 사람 감독 하 저속·소범위 실기 시운전
  4. 성능·안전 확인 후 점진 확대
- 각 단계에서 시뮬 대비 성능/안전 지표 차이를 **정량화**하고, 갭이 크면 도메인 랜덤화·시스템 식별·잔차 학습(residual RL)으로 되돌린다.

## 6. 평가 대상은 배포 그대로

- 안전 계층·정규화(관측/보상)·추론 경로를 **실제 배포 구성 그대로** 포함해 평가한다. 학습 편의용 래퍼(보상 shaping·시간제한 truncation 등)가 배포에 없다면 그 차이가 결과를 왜곡한다.
- 정규화 통계(VecNormalize 등)는 저장본을 그대로 로드해 평가한다 — 재계산 금지.

## 7. 워스트케이스·적대적 외란

- 평균이 아니라 **최악 성능/최대 제약 위반**을 본다 — 안전은 tail(꼬리 분포)이 결정한다.
- 최악 초기조건·최악 외란 시퀀스·최악 파라미터 조합을 탐색한다(그리드 스윕·최적화·적대적 섭동).
- 판정: 워스트케이스에서도 안전 제약이 유지되어야 실기 후보 자격이 있다.

## 8. 엣지·경계 케이스

- 관측 공간 경계, 액션 포화(saturation), 초기조건 극단, 센서 결측/스파이크, 통신 지연·드롭.
- 정책이 학습 분포 밖(OOD) 관측에서 어떻게 행동하는지 확인한다 — 안전 계층이 방어하는지, 폴백으로 넘어가는지.

## 9. 비상 정지·폴백 동작 확인

- 안전 계층(action clipping/shielding)이 위반 액션을 **실제로 차단**하는지 주입 테스트로 검증한다.
- 폴백 고전 제어기로의 전환(정책 실패·NaN·추론 지연 초과 시)과 비상 정지 경로 동작을 확인한다.
- 추론 지연 초과·정책 출력 이상(NaN/발산) 시 시스템이 **안전 상태로 수렴**하는지 확인한다([CRITICAL] 항목).

## 10. 장비 제어 실무 판정 기준

RL 정책도 고전 제어 사양서와 **같은 언어·같은 잣대**로 판정해야 실무에서 수용된다.

| 지표 | 정의 | 판정 예 |
|------|------|---------|
| 허용 오차(정상상태 오차) | 목표 대비 정착 후 잔류 오차 | 허용 밴드(±ε) 내 |
| 정착 시간(settling time) | 허용 밴드에 진입·유지까지 걸린 시간 | 사양 이하 |
| 오버슈트(overshoot) | 목표를 초과한 최대치 | 사양 % 이하 |
| 상승 시간 등 과도응답 | 필요 시 rise time 등 | 사양 |
| 제약 위반율 | §1 | 안전-크리티컬 0 |
| 안전 마진 | 위치/토크/속도 한계까지 여유 | 규정 마진 확보 |

- 각 이슈에 심각도를 부여한다: **CRITICAL**(안전 위반·실기 금지) / **MAJOR**(성능·사양 미달·조건부) / **MINOR**(개선 권장) / **INFO**(참고).

## 11. 실기 전환 가드 게이트

시뮬 전 항목 PASS 후에도 실기 투입 전 아래를 명시 확인한다. **하나라도 미충족이면 실기 배포 [CRITICAL] 보류.**

- [ ] 안전 계층(clipping/shielding) 활성·주입 테스트 통과(§9)
- [ ] 폴백 고전 제어기 상시 대기·전환 동작 확인(§9)
- [ ] 비상 정지 경로 검증(§9)
- [ ] 제약 위반율 0 — 워스트케이스 포함(§1, §7)
- [ ] 실기 파라미터가 학습/랜덤화 분포 내(§4)
- [ ] deterministic 정책·추론 지연 예산 충족(지연 초과 시 폴백)
- [ ] 배포 구성 그대로 평가(정규화·안전 계층 포함, §6)
- [ ] 사람 감독 하 저속·소범위 시운전 계획(§5)
- [ ] 실기 데이터 로깅·롤백 계획
- [ ] 성능은 `evaluation-protocol.md` 기준(다중 시드·베이스라인) 충족

> 이 게이트는 `SKILL.md`의 "실기 전환 가드 게이트"와 동일 계약이다.
