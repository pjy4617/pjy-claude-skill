# 강화학습 적용 가능성 체크리스트 + Go/No-Go 결정 규칙

> **용도**: rl-assess의 4단계에서 항목별로 평가해 리스크를 심각도화하고, 마지막에 Go/조건부 Go/No-Go를 낸다.
> **원칙**: 이 체크리스트는 RL을 정당화하기 위한 것이 아니라 **RL을 배제할 근거를 먼저 찾기** 위한 것이다.
> 심각도 표기: **CRITICAL / MAJOR / MINOR / INFO** (레포 관례). CRITICAL은 단독으로 No-Go 사유가 될 수 있다.

## A. 문제 성격 (RL이 필요한가)

| # | 항목 | 판정 기준(불리 → 심각도) | 심각도 |
|---|------|------------------------|--------|
| 1 | 고전 제어 충족 여부 | 대상이 선형·저차원이고 모델이 있으면 LQR/MPC로 충분 → RL 불필요 | CRITICAL |
| 2 | 현 제어기 개선 여지 | 현 PID/제어기가 튜닝·검증 미완이면 RL 이전에 그것부터 | MAJOR |
| 3 | 비선형·고차원·접촉 | 모델링 어려운 비선형/접촉풍부/하이브리드 동역학이면 RL 유리 | INFO(유리 신호) |
| 4 | 다목적·적응 요구 | 상충 목표 절충·환경 변화 적응이 핵심이면 RL 유리 | INFO(유리 신호) |
| 5 | 문제 정식화 성립 | MDP 정식화가 성립하나(마르코프성·보상 명세 가능) — `mdp-formulation.md` | CRITICAL |

## B. 데이터·환경 가용성 (RL이 가능한가)

| # | 항목 | 판정 기준(불리 → 심각도) | 심각도 |
|---|------|------------------------|--------|
| 6 | 시뮬레이터 존재 | 온라인 RL은 대량 상호작용 필요 — 시뮬레이터 없고 실기 탐색 불가면 온라인 RL 불가 | CRITICAL |
| 7 | 시뮬레이터 충실도 | 시뮬레이터가 있어도 검증 안 됐으면 학습 정책이 실기에서 무효(sim-to-real 갭) | MAJOR |
| 8 | 로그 데이터 | 시뮬레이터 없고 과거 운전 로그가 충분·다양하면 **오프라인 RL(CQL/IQL)** 후보 | INFO(경로 신호) |
| 9 | 샘플 예산 | 필요 스텝(수십만~수천만)을 시간·비용 내 확보 가능한가 | MAJOR |
| 10 | 온라인 탐색 허용 | 실기에서 무작위 탐색이 안전상 불가하면 온라인 학습 배제 | CRITICAL |

## C. 안전·검증 (RL을 배포할 수 있는가)

| # | 항목 | 판정 기준(불리 → 심각도) | 심각도 |
|---|------|------------------------|--------|
| 11 | 안전 크리티컬성 | 위반 시 장비 손상/인명 위험이면 무제약 정책 금지 — 안전 계층·폴백 필수 | CRITICAL |
| 12 | 안전 계층 실현성 | action clipping·shielding·폴백 고전 제어기·비상 정지를 넣을 수 있는가 | MAJOR |
| 13 | 검증 가능성 | 블랙박스 정책을 인증·검증할 수단(테스트 범위·보수적 한계)이 있는가 | MAJOR |
| 14 | 보상 명세 난이도 | 목표를 편법 없이 보상으로 인코딩 가능한가(reward hacking 위험) | MAJOR |
| 15 | 재현성 감내 | 통계적 성능(시드 분산)을 조직·인증 체계가 수용하는가 | MINOR |

## D. 배포·운영 (실기에서 굴러가는가)

| # | 항목 | 판정 기준(불리 → 심각도) | 심각도 |
|---|------|------------------------|--------|
| 16 | 실시간 추론 예산 | 정책(보통 소형 MLP)의 추론 지연이 제어 주기 안에 드는가(대개 μs 수준으로 여유, 대형망은 확인) | MAJOR |
| 17 | 장비 인터페이스 | 관측 수집·행동 인가 경로가 결정론적 지연으로 확보되는가 | MINOR |
| 18 | 비정상성·유지보수 | 마모·드리프트로 정책 열화 시 재학습·모니터링 체계가 있는가 | MINOR |
| 19 | 팀 역량·운영 | RL 파이프라인을 유지보수할 인력·MLOps가 있는가 | MINOR |
| 20 | ROI | RL 도입·유지 비용 대비 성능 이득이 대안(고전/하이브리드)을 능가하는가 | MAJOR |

## Go/No-Go 결정 규칙

판정은 개별 심각도 합산이 아니라 **아래 규칙을 순서대로 적용**한다. 상위 규칙이 먼저 걸리면 그것으로 확정한다.

1. **즉시 No-Go (고전 제어 권장)**
   - #1이 성립(선형·저차원·모델 有 → LQR/MPC 충분) → **No-Go**. RL이 들여올 리스크가 이득을 정당화하지 못함.
   - #5 불성립(문제가 MDP로 정식화 불가 — 관측 근본 부족 + 상태 추정 불가) → **No-Go**.

2. **즉시 No-Go (안전상 학습 불가)**
   - #11 안전 크리티컬 + #6 시뮬레이터 없음 + #10 온라인 탐색 불가 → **No-Go**.
     안전하게 학습할 경로가 없음. (단 #8 로그 데이터가 충분하면 → "조건부 Go: 오프라인 RL 검토"로 강등)

3. **조건부 Go (선결 조건 충족 시)**
   - #6/#7 시뮬레이터 미확보·미검증이 유일 장벽 → **조건부 Go**: "고충실도 시뮬레이터 확보·검증 후 진행".
   - #8 로그 데이터만 있고 온라인 탐색 불가 → **조건부 Go**: "오프라인 RL(CQL/IQL) 경로로 진행, 배포 전 보수적 정책 평가(OPE)".
   - #2 현 제어기 미튜닝 → **조건부 Go/보류**: "고전 제어 개선을 먼저 시도하고, 성능 천장 확인 후 재검토".

4. **Go (RL 적합)**
   - #3/#4 유리 신호(비선형·고차원·다목적·적응) + #6 시뮬레이터 확보·검증 + #11 안전 계층 실현 가능 + #16 실시간 예산 충족.
   - 이때도 **안전 계층·폴백·시뮬레이터 우선 검증·가드형 실기 전환**을 전제로만 Go.

> **판정 문구는 근거와 함께.** "No-Go" 하나로 끝내지 말고, 왜 그런지와 **대안 경로**(고전/하이브리드/조건 충족)를 반드시 제시한다.

## RL이 유리한 경우 vs 불리한 경우 (대비표)

| 차원 | RL이 유리 | RL이 불리(고전 제어 우선) |
|------|-----------|--------------------------|
| 동역학 | 비선형·고차원·접촉풍부·모델링 난해 | 선형·저차원·정확한 모델 존재 |
| 목표 | 다목적 절충·장기 최적·환경 적응 | 단일 목표·명확한 사양(정착시간 등) |
| 환경 | 고충실도 시뮬레이터 有 또는 대량 상호작용 가능 | 시뮬레이터 없음·실기 탐색 불가 |
| 데이터 | 풍부한 로그(오프라인 RL) 또는 값싼 샘플 | 데이터 희소·수집 비용 큼 |
| 안전 | 안전 계층·폴백 구성 가능, 여유 마진 존재 | 안전 크리티컬 + 안전 계층 구성난이 |
| 검증 | 통계적 성능 수용 가능 | 형식 보장·인증 필수(항공/의료 등) |
| 실시간 | 소형 정책이 제어 주기 내 추론 | 극한 저지연 + 대형 모델 필요 |
| 개선 여지 | 고전 제어가 성능 천장에 도달 | 현 제어기 튜닝·구조 개선 여지 남음 |

> **가장 흔한 함정**: "새 기술이니 RL을 쓰자"는 동기. 실무 판단은 정반대다 — **고전 제어로 안 되는 이유를 증명하지 못하면 RL을 쓰지 않는다.**
> 대부분의 산업 제어 문제는 이 표의 오른쪽에 속하며, RL이 정당화되는 경우는 소수다. 그 소수를 정직하게 가려내는 것이 이 게이트의 가치다.

## 심각도 가중 원칙

- **CRITICAL 1건이면 그 자체로 No-Go 또는 조건부 Go 사유**가 될 수 있다(합산하지 않는다). 예: #1(고전 제어 충족),
  #5(정식화 불가), #6+#10+#11 조합(안전상 학습 불가)은 단독/조합으로 판정을 결정한다.
- MAJOR는 "배포 전 반드시 해소해야 할 리스크"로, 다수 누적되면 조건부 Go로 강등하는 신호다.
- MINOR/INFO는 판정을 뒤집지 않지만 리포트에 완화책과 함께 기록해 이후 단계로 전달한다.
- **INFO(유리 신호)** 항목(#3·#4·#8)은 심각도가 아니라 "RL로 갈 근거"의 강도 표시다 — 이것이 강하고 CRITICAL이 없어야 Go로 간다.

## 적용 예시 (체크리스트 → 판정)

### 예시 1 — 반송 컨베이어 장력 제어 (전형적 No-Go)

- #1: 근사 선형 1차 시스템, 모델 확보 가능 → **CRITICAL(고전 충족)**
- #2: 현 PI 제어기 튜닝 미완 → MAJOR
- #6/#7: 시뮬레이터 없음 → CRITICAL(온라인 학습 불가)
- #11: 라인 정지 시 생산 손실(안전 크리티컬 아님, 가용성 크리티컬)

→ 규칙 1 적용(#1 성립) → **No-Go**. 권장: PI 재튜닝 → 부족 시 제약 있으면 MPC. RL 불필요.

### 예시 2 — 다관절 조립 로봇의 접촉풍부 삽입(peg-in-hole) (조건부 Go → Go)

- #3: 접촉풍부·비선형 동역학, 모델링 난해 → INFO(강한 유리 신호)
- #4: 힘/위치 다목적 절충 → INFO(유리 신호)
- #6: 고충실도 접촉 시뮬레이터 확보 가능 → 확보 시 CRITICAL 해소
- #10: 실기 온라인 탐색 불가(부품 손상) → 시뮬레이터+오프라인으로 우회
- #11: 안전 계층(힘 한계·shielding)·폴백(위치 제어) 구성 가능 → MAJOR 관리 가능
- #16: 소형 정책, 제어 주기 내 추론 여유

→ 규칙 3(조건부 Go: 시뮬레이터 확보·검증) → 확보되면 규칙 4(Go). 단, **하이브리드(residual/힘제어 기반) 우선**,
  시뮬레이터 우선 검증 → 가드형 실기 전환 전제. 순수 end-to-end 토크 제어는 지양.

> 두 예시의 차이는 "새 기술 여부"가 아니라 **고전 제어의 충족 가능성과 안전한 학습 경로의 존재 여부**다.
> rl-assess는 항상 이 두 축으로 먼저 가른다.
