# MDP 정식화 가이드 (제어 문제 → 마르코프 결정 과정)

> **핵심 전제**: 강화학습 프로젝트 실패의 대부분은 알고리즘이 아니라 **문제 정식화**에서 온다.
> 상태가 마르코프하지 않거나, 보상이 목표를 잘못 인코딩하거나, 에피소드 경계를 틀리면
> 어떤 알고리즘도 원하는 정책을 학습하지 못한다. 이 문서는 rl-assess가 MDP 초안을 세울 때의 기준이다.

## 0. MDP 5요소 (S, A, P, R, γ)

강화학습은 제어 문제를 **마르코프 결정 과정(MDP)** `(S, A, P, R, γ)`로 본다.

- `S` — 상태공간(state space)
- `A` — 행동공간(action space)
- `P(s' | s, a)` — 전이 확률(transition dynamics)
- `R(s, a, s')` — 보상 함수(reward)
- `γ ∈ [0, 1)` — 할인율(discount factor)

목표는 기대 할인 누적 보상 `E[ Σ_t γ^t r_t ]`를 최대화하는 정책 `π(a|s)`를 찾는 것이다.
정식화 단계에서 이 5요소를 **제어 문제의 물리량으로 명시적으로 매핑**한다.

## 1. 상태공간 S — 관측 vs 완전상태, 마르코프성

가장 중요한 질문: **"현재 관측만으로 최적 행동을 결정할 수 있는가?"** (마르코프성)

- **마르코프성(Markov property)**: 미래가 현재 상태에만 의존하고 과거 이력과 무관해야 한다.
  위치만 관측하고 속도를 빼먹으면(2차 시스템) 마르코프하지 않다 — 최적 제어에 속도가 필요하기 때문.
  → 이런 경우 **속도·가속도를 상태에 포함**하거나, 최근 관측을 **스택(frame stacking)**하거나,
     **순환 정책(RNN/LSTM, 예: RecurrentPPO)**으로 이력을 요약한다.
- **관측(observation) vs 완전상태(full state)**: 센서로 볼 수 있는 것이 관측, 동역학을 결정하는 것이 완전상태.
  둘이 다르면 문제는 **POMDP(부분관측 MDP)**다. 노이즈·지연·결측·미관측 물리량(마찰·온도·부하)이 원인.
  - POMDP 대응: 관측 히스토리 사용, 상태 추정기(칼만 필터 등)로 상태를 복원해 RL에 공급, 순환 정책 사용.
- **상태 스케일링**: 위치(mm)·속도(mm/s)·전류(A)처럼 스케일이 크게 다르면 학습이 불안정하다.
  관측 정규화(running mean/std, 예: `VecNormalize`)를 전제로 설계한다.
- **차원**: 상태가 클수록 샘플 요구가 커진다. 물리적으로 불필요한 신호는 제외해 차원을 최소화한다.

**체크**: (a) 상태가 마르코프한가? (b) 관측=완전상태인가, POMDP인가? (c) 스케일 정규화가 필요한가?

## 2. 행동공간 A — 연속 / 이산 / 혼합, 스케일

- **연속(continuous)**: 토크·속도·위치 지령처럼 실수 벡터. `Box` 공간. → SAC/TD3/PPO 후보
  (DDPG는 불안정으로 신규 첫 선택 비권장 — `rl-design`의 algorithm-catalog 참조).
- **이산(discrete)**: 스위칭·모드 선택·on/off. `Discrete`/`MultiDiscrete`. → DQN 계열/PPO 후보.
- **혼합(hybrid)**: 이산 모드 + 연속 파라미터. 파라미터화 행동공간 또는 문제 분해 필요.
- **행동 스케일·레이트 제한**: 물리 액추에이터의 범위·변화율 한계를 행동공간에 반영한다.
  RL 정책은 보통 `[-1, 1]`로 출력하고 환경 래퍼에서 물리 단위로 되돌린다(rescale).
  급격한 행동 변화(chattering)를 막으려면 **행동 변화율 페널티** 또는 저역통과 필터를 둔다.
- **행동 vs 지령 계층**: RL이 최종 토크를 직접 낼지, 기존 제어기의 **세트포인트/게인을 조정**할지 결정한다.
  후자(하이브리드)는 안전·검증이 훨씬 쉽다 — `rl-vs-classical.md`의 residual/게인튜닝 패턴 참조.

**체크**: (a) 연속/이산/혼합? (b) 물리 한계·레이트 제한이 반영됐나? (c) 직접 제어인가 상위 조정인가?

## 3. 보상 함수 R — 즉시/지연, 희소/조밀

**보상은 "무엇을"만 인코딩하고 "어떻게"는 지시하지 않는다.** 잘못된 보상은 reward hacking을 부른다.

- **조밀(dense) vs 희소(sparse)**: 매 스텝 정보를 주면(오차 제곱 등) 학습이 쉽지만 shaping 편향 위험.
  성공/실패에만 보상을 주면(희소) 진짜 목표에 충실하지만 탐색이 어렵다.
- **즉시 vs 지연(delayed) 보상**: 결과가 나중에 나타나면(수율·정착) credit assignment가 어렵다.
  할인율 `γ`와 에피소드 길이가 지연 신용 할당 능력을 좌우한다.
- **다목적·제약**: 성능(추종 오차) + 에너지 + 안전 위반 등 상충 목표를 가중합할지, **제약(constraint)**으로
  분리할지 결정한다. 안전은 보상에 섞기보다 **제약 MDP/shielding**으로 분리하는 것이 실무적으로 안전하다
  (설계 상세는 rl-design의 `reward-and-safety.md`).
- **reward hacking**: 대리 지표를 최적화하다 진짜 목표를 배신하는 현상(예: 정착시간 보상만 주면 오버슈트로 목표를 스치고 지나감).
  정식화 단계에서 "이 보상을 극대화하는 편법이 있는가?"를 반드시 자문한다.
- **potential-based shaping**: `F(s,s') = γΦ(s') − Φ(s)` 형태의 shaping은 최적 정책을 바꾸지 않는다(정책 불변성).
  임의 shaping은 정책을 왜곡할 수 있으므로 potential 기반을 우선한다.

**체크**: (a) 보상이 진짜 목표를 인코딩하나? (b) 조밀/희소·즉시/지연? (c) 편법(hacking) 여지? (d) 안전은 제약으로 분리했나?

## 4. 전이 P — 결정론 vs 확률론

- **결정론적(deterministic)**: 같은 (s,a)면 같은 s'. 시뮬레이터가 결정론적이면 재현성은 좋지만 과적합 위험.
- **확률론적(stochastic)**: 노이즈·외란·모델 불확실성. 실제 장비는 항상 확률론적이다.
- **도메인 랜덤화(domain randomization)**: sim-to-real 갭을 줄이려 시뮬레이터 파라미터(마찰·질량·지연)를
  학습 중 무작위화해 강건한 정책을 유도한다. 정식화 단계에서 "무엇이 실기에서 달라질 수 있는가"를 나열한다.
- **비정상성(non-stationarity)**: 마모·온도 드리프트로 동역학이 시간에 따라 변하면 고정 정책이 열화된다.
  온라인 적응 또는 주기적 재학습 전략을 전제한다.

**체크**: (a) 결정/확률? (b) 실기에서 변하는 파라미터는? (c) 도메인 랜덤화 대상은? (d) 비정상성이 있나?

## 5. 에피소드 경계 — terminated vs truncated (Gymnasium 5-튜플)

**Gymnasium API는 종료를 두 가지로 명확히 구분한다** (구 Gym의 단일 `done`과 다름):

- `terminated=True` — **MDP의 진짜 종료 상태**에 도달(목표 달성, 실패/고장, 안전 한계 위반 등 환경 동역학의 일부).
- `truncated=True` — **동역학과 무관한 외부 절단**(시간 제한 도달, 에피소드 최대 길이 등).

이 구분은 **가치 부트스트래핑에 직접 영향**을 준다:
- `terminated`이면 종료 상태 이후 가치는 0 — 부트스트랩하지 않는다.
- `truncated`이면 에피소드는 끊겼지만 MDP는 계속됨 — **마지막 상태의 가치를 부트스트랩해야** 편향이 없다.
- 이 둘을 혼동(구 Gym식 단일 `done`으로 처리)하면 시간 제한이 있는 태스크에서 가치 추정이 편향된다.

- `reset(seed=...) -> (observation, info)`
- `step(action) -> (observation, reward, terminated, truncated, info)` — **5-튜플**

**체크**: (a) 진짜 종료 조건(terminated)은? (b) 시간 제한(truncated)은? (c) 둘을 올바르게 분리했나?

## 6. 할인율 γ

- `γ`는 미래 보상의 현재 가치 비중. `γ→1`이면 장기 시야(정착·수율 등 지연 목표에 필요),
  `γ→0`이면 근시안(즉시 반응). 유효 시야 ≈ `1/(1−γ)` 스텝.
- 제어 주기가 짧을수록(고주파) 같은 물리 시간을 담으려면 `γ`를 1에 더 가깝게 잡는다.
- 일반적 시작값은 `0.99`(태스크·주기에 따라 조정) — 값 자체보다 **유효 시야가 목표 지연을 담는가**로 판단.

## 7. 정식화 산출 체크리스트 (rl-assess 리포트 §2 "MDP 초안"에 반영)

- [ ] 상태공간 정의 + 마르코프성 확보 방안(속도 포함/프레임 스택/순환/상태추정)
- [ ] 관측 vs 완전상태 구분 → MDP인가 POMDP인가 명시
- [ ] 행동공간(연속/이산/혼합) + 물리 한계·레이트 제한 + 직접제어/상위조정 결정
- [ ] 보상 초안 + reward hacking 자기점검 + 안전의 제약 분리 여부
- [ ] 전이 성질(결정/확률) + 도메인 랜덤화 대상 + 비정상성
- [ ] 에피소드 경계(terminated vs truncated) 명확 분리
- [ ] 할인율 초안과 유효 시야가 목표 지연을 담는지 확인

> 이 초안이 부실하면 이후 알고리즘 선정·구현이 아무리 좋아도 실패한다.
> rl-assess는 정식화가 성립하지 않으면(예: 관측이 근본적으로 부족하고 상태 추정도 불가) 그 자체를 No-Go 근거로 삼는다.
