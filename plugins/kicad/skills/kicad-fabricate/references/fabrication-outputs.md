# 제조 출력 — 팹 프로파일과 산출물 검증

`kicad-fabricate` 스킬 단계 4~8 의 참조 문서. 명령 플래그는 로컬 `kicad-cli 10.0.6` 으로 실측했다.

> **팹 규격은 바뀐다.** 아래 프로파일은 **출발점**이며, 발주 직전에 팹의 최신 문서로 확인한다.
> 이 문서가 판정할 수 있는 것은 "KiCad 가 무엇을 어떻게 뽑는가" 까지다.

---

## 1. 팹 프로파일

### 1.1 요약 표

| 항목 | 일반(범용) | JLCPCB | PCBWay |
|------|-----------|--------|--------|
| 거버 포맷 | RS-274X | RS-274X | RS-274X |
| X2 확장 | 그대로 둔다(기본 X2 on) | 그대로 둔다 | 그대로 둔다 |
| X2 를 끄는 경우 | 팹 CAM 이 X2 를 거부할 때 `--no-x2` | 위와 같음 | 위와 같음 |
| 파일 확장자 | Protel 기본(`.gtl/.gbl/.gts/…`) | Protel 기본 | Protel 기본 |
| 드릴 포맷 | Excellon | Excellon | Excellon |
| 드릴 단위 | mm | mm | mm |
| PTH/NPTH | 분리(`--excellon-separate-th`) | 분리 | 분리 |
| 드릴 맵 | 선택(`gerberx2` 또는 `pdf`) | 선택 | 선택 |
| 원점 | 드릴/배치 원점 통일 | 드릴/배치 원점 통일 | 드릴/배치 원점 통일 |
| 위치 파일 | CSV, mm | CSV, mm (CPL) | CSV, mm |
| 위치 파일 헤더 | KiCad 기본 그대로(7열) | `Designator,Mid X,Mid Y,Layer,Rotation` **5열로 재배치**(1.4 참조) | 팹 템플릿 확인 |
| BOM | CSV, MPN 필수 | CSV, `Comment/Designator/Footprint/LCSC` 계열 | CSV, MPN 필수 |
| 전달 형태 | 거버+드릴 zip 1개 | 거버+드릴 zip 1개, BOM·CPL 은 별도 | 거버+드릴 zip 1개 |
| 파일명 | 공백 없는 이름 권장 | 공백 있는 이름은 CAM 이 거부하는 경우가 있다 | 위와 같음 |

`--layers` 에는 **표준 이름**(`F.Cu`, `In1.Cu`, `Edge.Cuts` …)을 쓰는 것을 권장한다.
다만 kicad-cli 10.0.6 은 **개명된 이름도 받는다** — `F.SilkS` 를 `F.Silkscreen` 으로 개명한 보드에
`--layers "F.Silkscreen"` 을 넘겨 정상 플롯됨을 실측했다.
출력 **파일명**은 어느 쪽이든 사용자가 붙인 이름을 따른다(예: `F.Cu` 를 `Top` 으로 개명한 보드 → `*-Top.gtl`).
그래서 검증은 파일명 문자열이 아니라 **파일 수와 실제 목록**으로 한다(F2).

### 1.2 레이어 세트

2층 보드:

```
F.Cu,B.Cu,F.Mask,B.Mask,F.Silkscreen,B.Silkscreen,F.Paste,B.Paste,Edge.Cuts
```

4층 보드:

```
F.Cu,In1.Cu,In2.Cu,B.Cu,F.Mask,B.Mask,F.Silkscreen,B.Silkscreen,F.Paste,B.Paste,Edge.Cuts
```

- 보드의 실제 레이어 수는 `.kicad_pcb` 의 `(layers ...)` 블록으로 확인한다. 추측해서 `In*.Cu` 를 넣지 않는다.
- **`F.Paste`/`B.Paste` 는 스텐실용**이다. 스텐실을 주문하지 않으면 빼도 되지만, 넣어도 팹이 무시하므로 기본 포함이 안전하다.
- `Edge.Cuts` 는 반드시 `--layers` 에 넣는다. `--common-layers` 에만 넣으면 **독립 파일이 나오지 않고** 다른 플롯에 겹쳐 그려진다(실측).
- `F.Courtyard`/`*.Fab`/`*.Adhesive`/`Margin`/`User_*` 는 **넣지 않는다**. 제조에 쓰이지 않고 팹의 레이어 매핑을 혼란스럽게 한다.
  `--layers` 를 생략하면 이것들이 전부 나오므로, 레이어 세트는 항상 명시한다.

### 1.3 옵션 선택 근거

| 옵션 | 켜는 이유 | 끄는 경우 |
|------|----------|----------|
| `--subtract-soldermask` | 마스크 개구부 위의 실크를 지워, 패드에 실크가 인쇄되는 것을 막는다 | 팹이 자체 처리한다고 명시할 때 |
| `--use-drill-file-origin` | 거버 좌표를 드릴/배치 원점 기준으로 맞춘다 — 드릴·위치 파일과 좌표계 통일 | 절대 원점을 요구하는 팹 |
| `--no-x2` | 구형 CAM 이 X2 속성을 못 읽어 파일을 거부할 때 | 기본은 켜 두지 않는다(X2 를 그대로 쓴다) |
| `--no-netlist` | X2 넷리스트 속성이 팹 CAM 과 충돌할 때 | 기본은 그대로 둔다 |
| `--precision 6` | 기본값. 5 는 정밀도가 떨어진다 | 팹이 5 를 요구할 때만 |
| `--board-plot-params` | 보드에 저장된 플롯 설정을 쓴다 — 팀이 KiCad GUI 에서 세팅을 관리할 때 | 이 스킬처럼 명령행에서 세트를 고정할 때는 쓰지 않는다 |
| `--check-zones` | 존을 플롯 시점에만 채운다(보드 파일 미변경) | 보드를 정식으로 채워 저장했으면 불필요 |
| DNP 표기 3종(`--hdnp`/`--sdnp`/`--cdnp`) | 조립 도면(Fab 레이어)에서 DNP 를 구분해 보이고 싶을 때 | 팹 레이어를 출력하지 않으면 무관 |

### 1.4 위치 파일 (pick and place / CPL)

- KiCad 기본 헤더(10.0.6 실측): `Ref,Val,Package,PosX,PosY,Rot,Side` — **7열**
- 조립사 템플릿은 열 수와 순서가 다르다. **헤더 행만 바꾸면 안 된다** — 열을 삭제·재배치한다.
  JLCPCB CPL 은 `Designator,Mid X,Mid Y,Layer,Rotation` **5열**이고 `Layer`(KiCad 의 `Side`)의 위치도 다르다.

  | KiCad 열 | JLCPCB CPL 열 |
  |---|---|
  | `Ref` | `Designator` |
  | `Val` | (버림) |
  | `Package` | (버림) |
  | `PosX` | `Mid X` |
  | `PosY` | `Mid Y` |
  | `Rot` | `Rotation` (마지막 열) |
  | `Side` | `Layer` (4번째 열) |

  실측 변환 결과(354행): `C1,200.600000,-50.600000,bottom,180.000000`
- **좌표·회전 값 자체는 변환하지 않는다.** 열 이름과 순서만 맞춘다.
- **회전 기준**은 KiCad 풋프린트의 0도 방향이며, 조립사의 부품 방향 기준과 다를 수 있다.
  이 스킬은 회전을 보정하지 않는다 — 조립사 리뷰 단계에서 확인하도록 리포트에 남긴다.
- `--smd-only` 결과가 0행이면 THT 전용 보드다. **0행 파일을 보내지 않는다.**
- `--exclude-dnp` 로 제외한 부품 수는 BOM 의 DNP 수와 일치해야 한다.

### 1.5 발주용 BOM

- 그룹 키 우선순위: `MPN` → `Value + Footprint`. MPN 이 그룹 키가 아니면 정격이 다른 같은 값 부품이 한 행으로 합쳐진다.
- 회로도에 `MPN`/`Manufacturer`/`LCSC` 필드가 없으면 열은 빈 칸으로 나온다(실측 확인).
  이때 BOM 헤더와 검증 리포트에 **"MPN 부재 — 발주용 아님"** 을 명시한다.
- 조립용(`--exclude-dnp`)과 전체(DNP 포함) 두 벌을 뽑아 두면 조립사와의 확인이 한 번에 끝난다.

## 2. 산출물 검증 체크리스트

단계 8 에서 아래를 순서대로 확인한다. 각 항목은 **판정 방법이 있는 것만** 넣었다 — 눈으로 보고 "괜찮아 보인다" 는 판정으로 치지 않는다.

### F1. 게이트가 실제로 통과했는가

- DRC 를 **`--severity-error --severity-warning`** 으로 돌렸는가(`included_severities` 가 `['error','warning']`).
  `--severity-all` 은 사용자 DRC 예외까지 error 로 세므로 게이트 판정에 쓰지 않는다.
- `drc.json` 의 `violations` 중 `severity == "error"` 가 0건
- `unconnected_items` 가 0건
- `schematic_parity` 배열이 **검사되었고**(짝 회로도가 있었거나 베이스명 사본으로 돌렸고),
  **중단 사유 type**(`missing_footprint`, `extra_footprint`, `net_conflict`, `duplicate_footprints`)이 0건.
  KiCad 는 패리티를 전부 warning 으로 내므로 **severity 로 판정하지 않는다**(실측: 431건 전수 warning).
- 판정: 넷 중 하나라도 미확인이면 "미수행" 으로 적는다. 통과로 적지 않는다.
  특히 `schematic_parity` 가 **빈 배열이면 통과가 아니라 미수행**이다.

### F2. 거버 파일 수가 레이어 세트와 맞는가

- `--layers` 에 넘긴 레이어 수 + `.gbrjob` 1개 = 출력 파일 수
- 파일명은 사용자 레이어 이름을 따르므로 **문자열이 아니라 개수와 목록**으로 확인한다.
- 목록을 리포트에 그대로 싣는다.

### F3. 구리 레이어가 빠지지 않았는가

- 보드의 `(layers ...)` 에 있는 `*.Cu` 수 == 거버의 구리 파일 수
- 4층 보드에서 `In1.Cu`/`In2.Cu` 누락이 가장 흔한 사고다.

### F4. Edge.Cuts 가 독립 파일로 나왔는가

- 외곽선 파일이 없으면 팹이 보드 크기를 모른다.
- `--common-layers` 에만 넣었으면 나오지 않는다(실측) — `--layers` 에 있는지 확인한다.

### F5. 거버 파일이 비어 있지 않은가

- 각 파일 크기 > 0, 그리고 애퍼처 정의(`%AD`)와 좌표 명령(`X…Y…D0`)이 실제로 들어 있는지 확인한다.
- 존이 안 채워진 상태로 뽑으면 GND 플레인 거버가 사실상 비어서 나온다 — F6 과 함께 본다.

### F6. 존이 채워진 상태였는가

- **대상은 구리 존뿐이다.** keepout(룰 영역) 존은 `filled_polygon` 을 갖지 않으므로 세면 안 된다.
  `(zone` 을 통째로 세는 나이브 판정은 keepout 보드에서 100% 오탐이다(실측: `(zone` 245 / 구리 존 0).
  1차 수단은 `mcp__kicad__query_zones`(`zoneCount` 가 구리 존 수), 파일 파싱은 단계 2 의 awk 규칙을 쓴다.
- **구리 존이 0개면 "해당 없음"** 으로 적고 넘어간다. 미채움으로 적지 않는다.
- 구리 존 > 0 일 때만 단계 2 의 판정을 리포트에 옮긴다. "전부 채움" 또는 "미채움 n개 + 조치".
- 플롯 시점에만 채운 경우(`--check-zones`)는 **보드 파일과 거버가 다르다**는 사실을 명시한다.

### F7. 드릴이 PTH/NPTH 로 분리됐는가

- `*-PTH.drl`, `*-NPTH.drl` 두 파일 존재
- 각 파일의 홀 수를 세어 리포트에 적는다(Excellon 의 `T*` 툴 정의와 좌표 행 수).
- NPTH 가 0홀이면 파일이 비어 나올 수 있다 — 기구 홀이 정말 없는 보드인지 확인한다.

### F8. 드릴 맵이 생성됐는가 (요청 시)

- `*-drl_map.*` 파일 존재. 사람이 홀 크기를 검산하는 용도이므로, 팹이 요구하지 않으면 선택 사항이다.

### F9. 원점이 세 산출물에서 일치하는가

- 거버 `--use-drill-file-origin` / 드릴 `--drill-origin plot` / 위치 파일 `--use-drill-file-origin`
- 셋 중 하나만 다르면 조립 좌표가 통째로 어긋난다. **리포트에 "원점: 드릴/배치 원점으로 통일" 한 줄을 남긴다.**
- **보조 원점이 보드에 설정돼 있는지 먼저 확인한다**: `grep -c 'aux_axis_origin' "$PCB"`.
  0 이면 세 옵션이 모두 절대 원점(0,0)으로 폴백한다 — 서로 일치하므로 조립 좌표는 어긋나지 않지만,
  좌표가 보드 실제 위치로 나온다(실측: 거버 X177.165 mm / 드릴 X180.6 mm).
  팹·조립사가 "원점은 보드 좌하단" 을 기대하면 어긋나므로 리포트에 **"보조 원점 미설정 — 절대 원점 사용"** 을 적는다.

### F10. 위치 파일 행 수와 DNP 제외 수

- 행 수(헤더 제외)를 센다. 0행이면 THT 보드인지 확인하고, 맞으면 파일을 보내지 않는다.
- DNP 제외 수 = (전체 SMD 부품 수) − (위치 파일 행 수). BOM 의 DNP 수와 대조한다.

### F11. IPC-D-356 과 넷리스트가 일치하는가

- 단계 3.2 의 diff 결과를 그대로 옮긴다: 회로도에만 있는 핀 / 보드에만 있는 핀 / 넷 이름 불일치.
- **테스트 포인트 수 = `^317` 행 수 + `^327` 행 수.** `317` 은 스루홀 패드, `327` 은 SMD 패드다.
  SMD 가 대부분인 보드에서 `317` 만 세면 실제의 1% 만 본다(실측: `327` 1394 / `317` 16 / 합계 1410).
  리포트에는 합계와 함께 `(317 {n} / 327 {n})` 내역을 적는다.
- 넷 이름 비교는 **대문자 변환 + 뒤 14자**로 정규화한 뒤 한다(IPC 는 앞을 잘라 뒤 14자를 남기고 전부 대문자로 쓴다).

### F12. BOM 이 발주 가능한 상태인가

- 종류 수·총 수량을 센다.
- MPN 열이 전부 비어 있으면 **"MPN 부재 — 발주용 아님"** 을 헤더와 리포트에 적는다.
  이때 다음 절차도 함께 안내한다 — 회로도 심볼에 `MPN`/`Manufacturer`/`LCSC` 필드를 채운 뒤 단계 7 을 다시 돌린다.
- kicad-review 의 마크다운 BOM 과 종류 수·총 수량이 일치하는지 대조한다(같은 회로도에서 나왔으므로 맞아야 한다).
- **어긋나면 `exclude_from_bom` 심볼부터 의심한다.** 기구 홀·마커 심볼이 여기 걸린다.
  실측: `Hole(1mm)` 심볼 8개가 제외되어 생성 BOM 68종/363개 vs 사용자 BOM 70종/371개가 되었고,
  `--include-excluded-from-bom` 을 붙여도 되살아나지 않았다(10.0.6).
  대조 기준은 넷리스트 XML 의 `<comp>` 수다 — 이것과 BOM 총 수량을 먼저 맞춰 본다.

### F13. 체크섬을 남겼는가

- `SHA256SUMS` 파일 생성. 팹에 보낸 파일과 받은 파일이 같은지 되물을 근거가 된다.
- **기록된 줄 수 == 대상 파일 수**를 대조하고 그 값을 리포트에 `{기록}/{대상}` 으로 적는다.
  `sha256sum $(find ...)` 형태는 공백이 든 파일명을 조용히 빠뜨리면서도 파일은 만들어 낸다
  (실측: 20개 중 6개만 기록). 반드시 `find … -print0 | sort -z | xargs -0 sha256sum` 을 쓴다.

### F14. 리비전이 파일에 남았는가

- 산출물 디렉토리 이름 또는 리포트에 보드 리비전과 생성 날짜가 있는지 확인한다.
- 리비전 없는 산출물 묶음은 다음 발주 때 반드시 섞인다.

### F15. 팹 전달 패키지가 만들어졌는가

- 거버 + 드릴이 **zip 1개**로 묶였는가(1.1 의 전달 형태). BOM·CPL 은 별도 전달이므로 zip 에 넣지 않는다.
- **파일명에 공백이 없는가.** 산출물 파일명은 보드 파일명을 따르므로 보드명에 공백이 있으면 전부 옮는다.
  이름을 정리했으면 **체크섬을 다시 만든 뒤** zip 으로 묶는다(순서: 이름 정리 → 체크섬 → zip).
- **0홀 NPTH 파일은 넣지 않는다.** 위치 파일 0행을 보내지 않는 것과 같은 원칙이다.
- 드릴 맵은 팹이 요구할 때만 넣는다(F8 과 같은 판단).
- **스택업 사양(표면처리·솔더마스크 색·실크 색·유전율)은 산출물에 없다.** `.gbrjob` 에 있는 것은 보드 두께와
  동박 두께까지다. 발주 폼에 사람이 적어야 하므로 리포트 "확인 필요" 에 남긴다.
