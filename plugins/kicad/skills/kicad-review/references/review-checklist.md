# KiCad 범용 회로도 리뷰 체크리스트

> 이 체크리스트는 도메인에 무관하게 모든 KiCad 회로도에 적용 가능한 검증 항목이다.
> 도메인별 추가 항목은 SKILL.md의 "도메인별 추가 검증" 섹션을 참조한다.

## 판정 기준

| 등급 | 의미 | 조치 |
|------|------|------|
| ERROR | 하드웨어 손상 또는 동작 불가 | 반드시 수정 후 재검증 |
| WARN | 동작하지만 잠재적 문제 | 문서화 또는 개선 권장 |
| OK | 이상 없음 | - |
| N/A | 해당 회로에 미적용 | - |

## A. 전원 설계 (8항목)

| ID | 항목 | ERROR 조건 | 검증 방법 |
|----|------|-----------|----------|
| A1 | 모든 IC의 VCC/VDD 핀이 전원 네트에 연결되어 있는가 | 전원 핀 미연결 (플로팅) | 각 IC의 전원 핀을 네트리스트에서 추적 |
| A2 | 모든 IC의 GND/VSS 핀이 GND 네트에 연결되어 있는가 | GND 핀 미연결 | 같은 방법 |
| A3 | 각 IC의 VCC 핀 근처에 디커플링 캡(100nF)이 있는가 | 디커플링 캡 누락 | IC 주변 캡 탐색 |
| A4 | 벌크 캡(10μF~47μF)이 전원 입력부에 있는가 | WARN: 전원 리플 | 전원 커넥터/레귤레이터 출력 근처 |
| A5 | 전원 전압이 각 IC의 허용 범위 이내인가 | 정격 초과 → IC 손상 | 데이터시트 Abs Max 대조 |
| A6 | 전원 시퀀싱이 필요한 IC의 EN 핀이 올바르게 연결되었는가 | 시퀀싱 오류 → 래치업 | 데이터시트 Power-up Sequence 참조 |
| A7 | 각 전원 네트의 드라이버가 정확히 1개인가 (`power_out` 핀 1개 또는 PWR_FLAG 1개) | 0개 → ERROR (ERC `power_pin_not_driven`), 2개 이상 → ERROR (ERC `pin_to_pin`, power output 충돌) | 전원 네트별로 `power_out` 핀과 PWR_FLAG 심볼 개수를 센다 |
| A8 | 서로 다른 전압 레일이 직접 단락되지 않았는가 | 전원 단락 → 보드 손상 | 네트 이름으로 전압 레일 분리 확인 |

## E. ERC 수준 검증 (5항목)

**이 카테고리의 1차 근거는 ERC 실행 결과다.** `kicad-cli sch erc --format json --severity-all` 또는
MCP `run_erc`를 루트 시트에 한 번 돌리면 E1·E2·E5는 KiCad 엔진 판정으로 확정된다(계층 전체를 한 번에 본다).
ERC를 쓸 수 없을 때만 아래 "검증 방법"의 텍스트 추론 경로로 내려간다.

**ERC를 돌리기 전에 프로젝트가 무엇을 꺼 놨는지 먼저 읽는다.** `.kicad_pro`의 `erc.rule_severities`에서
`ignore`로 설정된 규칙은 `--severity-all`을 줘도 보고되지 않는다. 리포트에
"프로젝트가 무시하도록 설정한 규칙 N종"을 목록으로 남기고, `rule_severities`를 제거한 사본으로
재실행해 **가려져 있던 위반**을 별도 표로 싣는다(절차는 `../SKILL.md` 단계 3).
`power_pin_not_driven`·`pin_to_pin`·`endpoint_dangling`·`lib_symbol_mismatch`·`duplicate_reference`가
꺼져 있으면 그 사실 자체를 WARN으로 낸다. 실측에서 이 확인을 빠뜨리면 25건만 보이고
기본 설정에서는 41건이 나왔다 — E2(전원 핀 미구동) 10건이 통째로 가려져 있었다.
ERC 위반 항목에는 부품 참조가 없고 좌표(x/y)만 남으므로, 보고서에 "U2 pin 5"로 쓰려면
`list_schematic_components`(또는 넷리스트)의 핀 좌표와 대조하는 후처리가 필요하다.

| ID | 항목 | ERROR 조건 | 검증 방법 |
|----|------|-----------|----------|
| E1 | 동일 네트에 2개 이상의 출력이 연결되지 않았는가 | 출력 충돌 → 단락 | ERC `pin_to_pin` 위반. ERC 불가 시 네트별 핀 타입 분석 |
| E2 | 모든 `power_in` 핀의 네트에 `power_out` 또는 PWR_FLAG가 있는가 | 없으면 ERROR (ERC `power_pin_not_driven`) | 전원 네트 핀 타입 — 드라이버 개수 판정은 A7과 동일하므로 A7 결과를 재사용한다 |
| E3 | 네트 이름이 일관적인가 (대소문자, 언더스코어 통일) | WARN: 네트 분리 위험 | 네트 이름 패턴 |
| E4 | 같은 이름의 로컬 레이블이 서로 다른 시트에 있는가. 같은 시트에 같은 이름의 로컬·글로벌 레이블이 공존하는가 | 다른 시트의 동명 로컬 레이블은 연결되지 않음 → ERROR 후보. 동명 로컬·글로벌 공존은 다른 네트로 분리됨 → ERROR 후보 (ERC `same_local_global_label`) | 시트별 로컬 레이블 이름 목록을 교차 대조하고, 글로벌 레이블 이름과도 대조한다. 로컬(시트 내)과 글로벌(시트 간)을 함께 쓰는 것 자체는 정상 관행이다 |
| E5 | 와이어 끝점이 다른 와이어 중간에 닿는 T 접합에 junction 마커가 있는가 | 마커 없으면 실제 미연결 → ERROR. X 자 교차의 junction 은 의도치 않은 단락 후보 → WARN | ERC(미연결 끝점·`four_way_junction`)와 S2/S3 린트가 1차 근거. ERC·MCP 불가 시 넷리스트에서 T 접합 좌표와 `(junction ...)` 좌표 대조. 시각 확인은 V1과 동일 판정 |

## L. 제조사 공식 라이브러리 비교 (5항목)

회로도 심볼의 핀 정의를 **정본(定本)**과 대조하여 커스텀 심볼의 핀 오류를 사전에 차단한다.
핀 대조의 정본은 두 가지다 — (a) 로컬 `.kicad_sym`(KiCad 공식 라이브러리 또는 프로젝트에 들어 있는 벤더 심볼),
(b) 데이터시트의 Pin Description 표. SnapEDA·Ultra Librarian 같은 웹 사이트는 핀 테이블을 페이지에 노출하지 않고
로그인 후 zip 다운로드를 요구하므로 WebFetch로 대조할 수 없다 — **다운로드 링크 제공용**으로만 쓴다.

**MCP `list_symbol_pins`가 `not found`를 내면 카테고리를 포기하지 말고 `.kicad_sym`을 직접 파싱한다.**
라이브러리가 심볼을 `(symbol "LIB:NAME" …)` 형식으로 저장하면 이 도구는 전건 실패한다 —
벤더·SnapEDA 배포 심볼에서 흔한 형식이다. 실측에서 프로젝트 벤더 심볼 36개 중 MCP는 0개,
직접 파싱은 36개를 읽었다. 스크립트는 `kicad-parser.md`의 "`.kicad_sym` 심볼 핀 직접 파싱" 절에 있다.

| ID | 항목 | ERROR 조건 | 검증 방법 |
|----|------|-----------|----------|
| L1 | 핀 번호가 공식 라이브러리와 일치하는가 | 핀 번호 불일치 → 잘못된 패드에 연결 | 공식 심볼의 pin number vs 회로도 심볼 |
| L2 | 핀 이름이 공식 라이브러리와 일치하는가 | WARN: 이름 차이 (기능 동일하면) | 공식 심볼의 pin name vs 회로도 심볼 |
| L3 | 핀 총 개수가 일치하는가 | 핀 수 불일치 → 심볼 오류 | 공식 심볼의 총 핀 수 vs 회로도 심볼 |
| L4 | 풋프린트가 파트넘버의 패키지와 일치하는가 | 패키지 불일치 → 실장 불가 | 공식 풋프린트 vs 회로도 Footprint 필드 |
| L5 | 핀 타입(입력/출력/전원/양방향)이 올바르게 정의되었는가 | 전원 핀이 I/O로 정의됨 → ERC 미검출 | 공식 심볼의 pin type vs 회로도 심볼 |

**핀 대조 소스 순서**:
1. 프로젝트에 들어 있는 벤더 `.kicad_sym` — `list_symbol_pins`(`symbol`="Lib:Name", `schematicPath`로 프로젝트 sym-lib-table 해석). 다건은 `batch_list_symbol_pins`
2. KiCad 공식 라이브러리 — 같은 도구, 또는 `/usr/share/kicad/symbols/<Lib>.kicad_sym`을 Grep으로 `(pin ` 블록 추출
3. 데이터시트 Pin Description 표 — 커스텀/벤더 심볼 자체가 틀린 경우의 최종 정본
4. (다운로드 링크 제공용) SnapEDA / Ultra Librarian / Component Search Engine 웹 검색

`kicad-cli sym export`는 SVG만 지원하므로(실측: `kicad-cli sym --help`) 핀 데이터 추출에 쓰지 않는다.
`list_symbol_pins`는 "회로도 심볼 인스턴스 vs 라이브러리 정의"를 보는 1차 게이트이고,
"라이브러리 정의 자체가 맞는가"는 데이터시트로만 판정된다. L4(풋프린트 패키지)는 이 도구로 볼 수 없다.

## S. 구조 린트 (기계 판정, 5항목)

KiCAD-MCP-Server가 등록돼 있으면 회로도 구조 결함을 좌표·라인 번호와 함께 기계로 뽑는다.
V1/V3/V7의 1차 근거는 이 카테고리이며, PDF 육안 판정은 MCP가 없을 때의 폴백이다.
**린트 도구는 파일 하나만 읽는다 — 루트와 서브시트 전부에 시트마다 반복 호출한다.**
출력 상한은 도구마다 다르다(실측: `find_wires_crossing_symbols` 30건, `find_overlapping_elements` 20건).
`Found N`의 N과 실제 출력 줄 수를 비교해 다르면 보고서에 "린트 결과 절단됨"을 명시한다.

**S2·S4의 MCP 결과는 오탐 필터를 거친 뒤에야 쓴다.** 필터 전 결과를 그대로 옮기면 보고서가
잡음으로 덮인다 — 실측(371부품·8시트)에서 세 도구가 427건을 냈고 진짜 결함은 0건이었다.
필터 규칙과 스크립트는 `../SKILL.md` 단계 5 "오탐 필터"와 `kicad-parser.md`
"구조 린트 오탐 필터"에 있다. **필터 후에도 남은 건은 `[후보]`이며,
`get_schematic_view_region`으로 눈으로 확인하기 전까지 ERROR/WARN으로 확정하지 않는다.**
걸러낸 건수는 "제외 N건(사유)"로 함께 적는다.

| ID | 항목 | ERROR 조건 | 검증 방법 |
|----|------|-----------|----------|
| S0 | 파일이 S-expression으로 정상 파싱되는가 | 괄호/문자열 불균형, 고아 property → 파싱 실패 | `validate_schematic`(kicad-cli 없으면 `runKicadCli: false`). 결함 위치를 라인·컬럼으로 반환 |
| S1 | 핀에 닿지 않는 떠 있는 레이블이 없는가 | 레이블이 어느 핀에도 닿지 않음 → 네트 미형성 (V3와 같은 판정) | `list_floating_labels` — 레이블 이름/타입/좌표 |
| S2 | 한쪽 이상이 떠 있는 와이어가 없는가 | 와이어 끝점이 허공 → 미배선 (V7과 같은 판정) | `find_orphaned_wires` — 끝점 좌표. **필터 F1**: 끝점이 핀 번호가 빈 문자열인 심볼(테스트포인트·SMD 패드)의 핀 좌표와 일치하면 제외 — 도구가 `(number "")` 핀을 세지 않아 정상 연결을 dangling으로 본다(실측 29/29 제외) |
| S3 | 오프그리드 좌표가 없는가 | 0.5 mm 초과 이탈은 NEEDS HUMAN, 그 이하는 WARN. "보기엔 붙었는데 실제 미연결"의 주원인 | `lint_offgrid`(`gridSize` 기본 1.27). **`fix`를 넘기지 않는다** — 리뷰는 회로도를 수정하지 않는다 |
| S4 | 심볼을 관통하거나 서로 겹친 요소가 없는가 | 중복 전원 심볼(같은 좌표 2개)은 ERROR, 관통·겹침은 WARN (V2 일부와 같은 판정) | `find_wires_crossing_symbols`, `find_overlapping_elements`. **필터 F2**: 양쪽 레퍼런스가 같은 쌍(`U6 ↔ U6`)은 멀티유닛 자기 자신이므로 제외. **F3**: 상대가 멀티유닛/거대 심볼이면 배치된 그 유닛의 바운딩 박스로 재판정. **F4**: 와이어 끝점이 그 심볼의 핀 좌표와 일치하면 정상 접속이므로 제외 + 중복 보고 제거. 실측 64→27 / 334→2. 필드 텍스트(Reference/Value) 겹침은 이 도구 범위 밖 → V2 육안 유지 |

MCP 미등록 시: S0~S4는 수행 불가로 두고 V 카테고리 육안 판정으로 대체하며, 보고서에 "구조 린트 미수행 — MCP 미등록" 을 명시한다.

## P. 풋프린트 해석 (4항목)

회로도의 `Footprint` 속성은 `Lib:Name` 문자열일 뿐이다. 그 nickname이 `fp-lib-table`에서 실제로 풀리는지는
별도로 확인해야 하며, **여기서 실패하는 것이 Update PCB 실패의 1위 원인**이다.
파싱 방법은 `references/kicad-parser.md`의 "fp-lib-table 파싱" 절을 참조한다.

| ID | 항목 | ERROR 조건 | 검증 방법 |
|----|------|-----------|----------|
| P1 | 모든 부품에 `Footprint` 값이 있는가 | 빈 `Footprint` → 보드로 넘어가지 않음. **단 `exclude_from_bom`(회로도 `(in_bom no)`) 심볼은 제외** — 기구 표기용 마운팅 홀·전원 표기는 풋프린트가 없는 것이 정상이며 KiCad ERC도 문제 삼지 않는다 | 넷리스트 XML의 `<footprint>` 전수 수집 (빈 값 포함) 후 `<property name="exclude_from_bom"/>` 부품 제외. 제외 건수를 "제외 N건(BOM 제외 표시 부품)"으로 함께 적는다 (실측 9→1) |
| P2 | `Lib:Name`의 nickname이 fp-lib-table에서 풀리는가 | 미등록 nickname 또는 URI 경로 부재 | `list_library_table`(`tableType: "footprint"`, `scope: "project"` / `"global"`) 또는 전역+프로젝트 `fp-lib-table` 직접 파싱. KiCad 10의 `(type "Table")` 간접 행을 펼친 뒤 판정한다 |
| P3 | `.pretty` 디렉토리에 `<Name>.kicad_mod`가 실제로 있는가 | 파일 부재 → 실장 불가 | 해석된 URI 경로에서 파일 실존 확인 |
| P4 | 그 라이브러리를 KiCad가 **실제로 열 수 있는가** | 파일은 있는데 로드 실패 → 풋프린트 갱신 불가 | `kicad-cli fp export svg --fp <풋프린트 하나> --output <tmp> <lib>.pretty` 가 실패하면 ERROR. ERC `footprint_link_issues`가 1차 근거다 |

P2에서 `Lib:Name` 형식이 아닌 값(콜론 없음)도 ERROR로 낸다.

**P1~P3은 "있는가"만 본다 — "실존"과 "로드 가능"은 다르다.** `list_library_table`의
`exists: true` / `missingCount: 0`은 디렉토리 존재만 뜻하며 `.kicad_mod`를 파싱하지 않는다.
P4의 로드 시험이 없으면 이 차이가 리뷰에서 통째로 빠진다 — 실측에서 P1~P3을 전부 통과한
라이브러리 2개가 KiCad 10에서 로드에 실패했고(원인: 정확히 180도인 `fp_arc`),
같은 결함을 ERC가 24건으로 지적했다. 로드 시험 비용은 42개 라이브러리에 7.8초다.
D2/L4(패키지 일치)는 "풋프린트가 그 부품에 맞는가"를 보고, P는 "그 풋프린트가 존재하는가"를 본다 — 서로 대체하지 않는다.

## V. PDF 시각적 검토 (7항목)

kicad-cli로 PDF 내보내기 후 멀티모달 분석으로 검증한다.

**ERC(E)와 구조 린트(S)를 먼저 돌린 뒤에 본다.** V1·V3·V4·V7은 ERC와 S1~S3이 좌표 근거로 기계 판정하므로
그쪽 결과가 있으면 육안 재확인을 하지 않는다. PDF 육안이 담당하는 고유 영역은
**V2(필드 텍스트 겹침)·V5(신호 흐름 가독성)·V6(시트 간 일관성)** 세 항목이다.
ERC도 MCP도 없는 환경에서는 V1~V7 전부를 육안으로 보되, 보고서에 "기계 판정 미수행 — 육안 폴백" 을 명시한다.

| ID | 항목 | ERROR 조건 | 검증 방법 |
|----|------|-----------|----------|
| V1 | 와이어 끝점이 다른 와이어 중간에 닿는 T 접합에 junction(접합점) 마커가 있는가 | T 접합에 마커 없으면 전기적 미연결 → ERROR. X 자 교차는 마커가 없어야 정상이며, 마커가 있으면 의도치 않은 단락 후보 → WARN (ERC `four_way_junction`) | PDF에서 와이어 끝점이 닿는 지점과 단순 X 자 교차점을 구분해 확인 |
| V2 | 부품 심볼, 레이블, 값 텍스트가 서로 겹치지 않는가 | WARN: 가독성 저하 | PDF에서 텍스트/심볼 겹침 확인 |
| V3 | 네트 레이블이 와이어 끝에 정확히 연결되어 있는가 | 미세 이탈 시 미연결 | PDF에서 레이블-와이어 접점 확인 |
| V4 | 전원 심볼(VCC/GND)이 와이어에 올바르게 연결되어 있는가 | 떠 있는 전원 심볼 | PDF에서 전원 심볼 연결 확인 |
| V5 | 신호 흐름이 입력→왼쪽, 출력→오른쪽 관례를 따르는가 | WARN: 가독성 | PDF에서 전체 흐름 방향 확인 |
| V6 | 시트 간 계층 핀과 글로벌 레이블이 시각적으로 일관적인가 | WARN: 혼동 가능 | 루트 시트의 계층 핀 vs 서브시트 레이블 |
| V7 | 끊어진 와이어, 허공에서 끝나는 미완성 연결이 없는가 | 미배선 → 회로 미완성 | PDF에서 와이어 끝점 확인 |

## 검증 실행 순서

**원칙: 기계가 판정할 수 있는 것을 먼저 걷어내고, 남은 것만 사람이 본다.**
실무 회로도 리뷰는 ERC를 첫 단계로 돌린다 — 미연결 핀·다중 드라이버·PWR_FLAG 누락은
30초짜리 기계 판정이라 사람이 다시 볼 이유가 없다. 가장 비싼 단계(PDF 멀티모달 판독, IC별 웹 검색)를
맨 앞에 두면 기계가 이미 잡아낼 문제를 사람 시간으로 다시 찾는 셈이 된다.
비유하면 원고 교정에서 맞춤법 검사기를 먼저 돌리고 나서 문장을 읽는 것과 같다.

| 순서 | 카테고리 | 무엇을 쓰나 | 왜 여기인가 |
|------|----------|------------|------------|
| 1 | **E (ERC)** | `kicad-cli sch erc --format json --severity-all --output <파일> <루트.kicad_sch>` 또는 MCP `run_erc`. **루트 시트에 한 번**이면 계층 전체를 본다 | 기계 판정. 미연결·다중 드라이버·PWR_FLAG를 먼저 확정한다 |
| 2 | **P (풋프린트 해석)** | `list_library_table`(`tableType: "footprint"`) 또는 fp-lib-table 직접 파싱 | 기계 판정. 여기서 걸리면 Update PCB가 통째로 실패하므로 회로 내용을 보기 전에 확인한다 |
| 3 | **S (구조 린트)** | `validate_schematic`, `lint_offgrid`(`fix` 미사용), `list_floating_labels`, `find_orphaned_wires`, `find_wires_crossing_symbols`, `find_overlapping_elements` — **시트마다 반복** | 기계 판정. kicad-cli 없이도 동작하므로 직접 파싱 모드에서 특히 값이 크다 |
| 4 | **V (시각 검토)** | PDF 멀티모달 판독 | ERC·린트가 못 잡는 **V2/V5/V6**(텍스트 겹침·신호 흐름·시트 간 일관성)만 본다 |
| 5 | **L (라이브러리 핀 대조)** | `list_symbol_pins` / 로컬 `.kicad_sym` Grep → 데이터시트 Pin Description | 심볼 핀 오류를 회로 해석 전에 차단한다 |
| 6 | **A (전원)** | 넷리스트 추적 | 전원이 없으면 나머지 판정이 의미 없다 |
| 7 | **D (데이터시트)** | 웹 검색 + 권장 회로 대조 | IC별 권장 회로가 B/C 판정의 기준이 된다 |
| 8 | **B (핀 연결)** | 데이터시트 기준 필수 핀 대조 | D의 결과를 입력으로 쓴다 |
| 9 | **C (신호 무결성)** | 고속 신호·차동 쌍 검토 | |
| 10 | **F (도메인별)** | 감지된 도메인의 추가 항목 | 해당 시에만 |

이후 BOM 생성 → 종합 보고서 순으로 마무리한다.

**폴백**: kicad-cli도 MCP도 없으면 1~3단계를 수행할 수 없다.
이때는 기존 텍스트 추론 경로(넷리스트/직접 파싱 기반 E 카테고리 판정 + V1~V7 육안)로 내려가고,
보고서 머리에 "ERC·구조 린트 미수행 — 텍스트 추론 모드" 를 명시한다.

## 보고서 작성 원칙

- ERROR 항목에는 반드시 **데이터시트 근거**(섹션명, 테이블 번호, 페이지)를 명시한다
- "권장" 또는 "~인 것 같다" 같은 모호한 표현 대신, 데이터시트 원문을 인용한다
- 수정 조치는 구체적으로 제시한다 (예: "C5를 100nF에서 1μF로 변경" ← 이렇게)
- 확인할 수 없는 항목은 N/A로 표시하되 사유를 기술한다
