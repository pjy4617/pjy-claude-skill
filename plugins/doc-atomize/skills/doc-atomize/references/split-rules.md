# 분할 규칙 (split rules)

`split_md.py`가 따르는 결정적 규칙. 여기 적힌 것 외의 판단은 하지 않는다.

## 1. 크기 정책

| 파라미터 | 기본값 | 의미 |
|---|---|---|
| `--min-lines` | 40 | 이 미만이면 인접 형제와 병합 후보 |
| `--max-lines` | 250 | 이 초과면 하위 헤딩으로 하강 분할 |
| `--hard-max` | 400 | 하위 헤딩이 없어도 이 초과면 문단 폴백 분할 |

목표는 조각 하나가 **한 번에 읽어도 부담 없는 크기(대략 1~3k 토큰)** 가 되는 것이다.

## 2. 경계 우선순위

1. **기준 레벨 자동 판정** — 2회 이상 등장하는 가장 얕은 헤딩 레벨. H1 제목 1개 + H2 다수인 일반 문서는 H2가 기준이 된다. `--base-level`로 고정 가능.
2. **하강 분할** — 세그먼트가 `max-lines`를 넘으면 한 단계 아래 헤딩(H3→H4…)에서 다시 자른다. H6까지 내려간다.
3. **문단 폴백** — 더 내려갈 헤딩이 없는데 `hard-max`를 넘으면 **펜스 밖 빈 줄** 경계에서 자른다. 이렇게 생긴 뒷조각은 `kind: overflow`로 표시되고 제목에 `(계속)`이 붙는다.
4. **헤딩이 아예 없는 문서** — 처음부터 문단 폴백만 적용한다.

## 3. 병합 규칙

인접한 두 조각은 다음을 **모두** 만족할 때만 병합한다:

- 라인 범위가 맞닿아 있다 (`prev.end == next.start`) — 커버리지 연속성 보장
- **부모가 같다** (같은 상위 헤딩 아래)
- 둘 중 하나가 임계값 미만이다
- 합쳐도 `max-lines` 이하다
- 뒤 조각이 `overflow`가 아니다

**임계값은 두 종류다:**

| 상황 | 임계값 |
|---|---|
| 둘 다 최상위(장) 수준 헤딩 | `min-lines / 2` (기본 20줄) |
| 그 외 | `min-lines` (기본 40줄) |

장(章) 단위가 통째로 다른 장에 흡수되면 목차 번호가 끊겨 사람이 문서를 못 따라간다. 그래서 최상위끼리는 훨씬 작을 때만 병합한다.

**병합된 조각의 제목은 결합된다** — `14. 검증 기준 + 15. 핵심 리스크 및 대응 + …`. 셋 이상이면 `…`로 줄이되, 흡수된 헤딩 전체는 `contains`에 남아 인덱스 `↳` 줄에 노출된다. 문서 머리(preamble)가 첫 절에 흡수될 때는 그 절의 정체성을 따른다.

## 4. 절대 자르지 않는 것

- **코드펜스 내부** — ` ``` `/`~~~` 안의 `#`은 헤딩이 아니다. 여는 펜스와 같은 문자·같거나 긴 길이·info string 없음일 때만 닫힌 것으로 본다
- **선두 YAML 프론트매터** — 문서 첫 줄 `---` 블록. 내부의 `#`도 헤딩이 아니며, 블록은 첫 조각 본문에 그대로 실린다
- 표·리스트 블록 중간 (문단 폴백은 빈 줄에서만 자르므로 자연히 보존된다)

## 5. 슬러그 (파일명)

`--slug auto`(기본):
- 제목에 **CJK가 없으면** ASCII 슬러그 (`3. FPGA Pin Plan` → `3-fpga-pin-plan`)
- **CJK가 섞여 있으면 원문 보존** (`3. FPGA 핀 할당 계획` → `3-FPGA-핀-할당-계획`)
  ASCII만 남기면 `3-fpga`가 되어 식별성이 무너지기 때문이다
- 공백·`.`은 `-`로, 그 외 기호는 제거, 48자에서 자름
- 같은 슬러그가 겹치면 `-2`, `-3` 접미사 (원문에 중복 절 번호가 있는 문서에서 실제로 발생한다)

`--slug ascii`: 파일명에 ASCII만 허용하는 환경용. CJK 제목은 번호만 남을 수 있다.

최종 파일명은 `NNN-<slug>.md` — 3자리 순번이 앞에 붙어 **정렬 = 원문 순서**다.

## 6. 엣지케이스 동작 (검증됨)

| 입력 | 동작 |
|---|---|
| CRLF 문서 | LF로 정규화 후 분할, `line_ending: crlf` 기록 |
| BOM | 제거 후 처리 |
| 선두 프론트매터 | 첫 조각 본문에 그대로 보존 |
| 펜스 안 `#`/`##` | 헤딩으로 오인하지 않음 |
| 헤딩 0개 + 600줄 | 문단 폴백으로 3조각 |
| H2 하나 + 1200줄 | hard-max 폴백으로 5조각, 뒤 4개는 `(계속)` |
| 문서 전체가 40줄 미만 | 1조각 (쪼개지 않음) |
| 중복 헤딩 (`### 3.5`가 둘) | 슬러그 `-2` 접미사로 구분 |

## 7. 문서 유형별 옵션 튜닝

| 유형 | 권장 | 이유 |
|---|---|---|
| PRD·설계서 (장/절 구조 뚜렷) | 기본값 | H2=장 단위가 자연스러운 조회 단위 |
| API 레퍼런스 (항목이 많고 짧음) | `--min-lines 15 --max-lines 120` | 함수 하나 = 조각 하나에 가깝게 |
| 회의록·로그 누적본 | `--base-level 2 --max-lines 400` | 날짜별 덩어리 유지, 잘게 쪼개면 맥락 손실 |
| 튜토리얼 (단계가 길고 코드 많음) | `--max-lines 350` | 단계 중간이 잘리면 읽기 어렵다 |
| 표 위주 스펙시트 | `--max-lines 400` + 큐레이션 강화 | 자동 요약이 약해 수동 요약이 중요 |

조각 수가 80개를 넘으면 스크립트가 경고한다. 인덱스가 무거워지므로 `--max-lines`를 키워 재분할한다.

## 8. 커버리지 불변식

분할 결과는 항상 다음을 만족한다. 위반 시 스크립트가 즉시 실패한다.

```
part[0].start == 1
part[i].start == part[i-1].end + 1     (빈틈·겹침 없음)
part[-1].end  == 원본 총 줄수
```

이 불변식 + 본문 무편집이 곧 무손실 보증이며, `verify`가 재조립 sha256으로 이를 매번 재확인한다.
