full-stack 분해의 **순서**가 성립하는지 본다. 필드 표기 형식과 커버리지 표의 REQ 행 존재는
별도 정규식 채점자가 판정하므로 여기서 다시 보지 않는다.

통과 조건 (둘 다 만족):

- API 계약(조회·읽음 인터페이스) 확정이 백엔드 구현·프론트 구현보다 앞선 선행 작업으로 잡혀 있다. 계약 작업이 별도 TASK 또는 별도 그룹으로 존재하고, 구현 TASK의 선행에 그것이 들어 있으면 만족이다.
- 백엔드 작업과 프론트 작업이 구분돼 있고, 두 역할이 동시에 붙어야만 끝나는 TASK가 남아 있지 않다.

**위반이 아닌 것** (이것들로 실패시키지 마라):

- 계약 확정을 여러 TASK로 쪼갠 것(데이터 모델 / API 스키마 / 검증 하네스 등). 순서만 맞으면 된다.
- 그룹·마일스톤 이름이나 번호 체계가 예상과 다른 것.
- TASK 수가 많거나 적은 것, 문서가 긴 것.
- 범위 절단·우선순위 조정을 제안한 것.
- 답변 형식과 분량.

**필드 누락으로 실패시키려면 근거 요구사항·선행·규모 중 하나가 빠진 TASK를 이름으로 지목할 수 있어야 한다.**
지목할 수 없으면 그 사유로 실패시키지 마라.
