## 7. 요구사항

### REQ-001 — 주문 생성 API
- **강도**: MUST
- **설명**: 클라이언트가 상품·수량·배송지를 담아 주문을 생성할 수 있어야 한다.
- **수용 기준**:
  - AC-001-1: 유효한 요청에 대해 201과 주문 ID를 반환한다.
  - AC-001-2: 필수 필드 누락 시 400과 누락 필드명을 반환한다.

### REQ-002 — 재고 원자적 차감
- **강도**: MUST
- **설명**: 주문 확정 시 재고 차감은 주문 저장과 같은 트랜잭션에서 이루어져야 한다.
- **수용 기준**:
  - AC-002-1: 동시 100건 요청에서 재고 수량이 음수가 되지 않는다.

### REQ-003 — 주문 취소 API
- **강도**: MUST
- **설명**: 출고 전 주문은 취소할 수 있어야 하며 차감된 재고가 복원되어야 한다.
- **수용 기준**:
  - AC-003-1: 출고 전 취소 시 재고가 주문 전 수량으로 복원된다.
  - AC-003-2: 출고 후 취소 요청은 409를 반환한다.

### REQ-004 — 주문 목록 페이징
- **강도**: SHOULD
- **설명**: 사용자별 주문 목록을 커서 페이징으로 조회할 수 있어야 한다.
- **수용 기준**:
  - AC-004-1: 페이지당 20건과 다음 커서를 함께 반환한다.

### REQ-005 — 결제 게이트웨이 연동
- **강도**: MUST
- **설명**: 외부 PG를 통해 결제 승인·취소를 수행해야 한다.
- **수용 기준**:
  - AC-005-1: 결제 승인 실패 시 주문이 생성되지 않는다.
