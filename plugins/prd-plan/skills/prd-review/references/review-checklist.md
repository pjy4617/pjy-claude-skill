# 독립 검수 체크리스트 — 외부 문서용

`quality-rubric.md`(7카테고리·4등급)가 정본이고, 여기에는 **외부 문서를 볼 때만 필요한 항목**을 더한다.
외부 문서는 이 플러그인 규격을 따르지 않는 것이 정상이므로, **형식 미준수 자체를 결함으로 취급하지 않는다.**

## 0. 형식 차이 다루기

| 상황 | 처리 |
|------|------|
| REQ-ID가 없음 | 결함 아님. 단, **요구사항을 개별적으로 지목할 수 없다면** 추적성 MAJOR (구현·검증에서 누락이 생긴다) |
| AC 대신 "기대 결과" 등 다른 이름 | 이름은 무관. 내용이 관측 가능하면 통과 |
| 표/자유서술 혼재 | 결함 아님. 내용으로 판정 |
| 이 플러그인 규격으로의 변환 필요 | 지적이 아니라 **권고**로: "prd-write로 재구성하면 추적성 검증이 가능해집니다" |

## 1. 외부 문서 특유의 함정

- [ ] **작성 시점이 오래됨** — 문서가 현재 상태를 반영하는가. 갱신 이력·버전이 있는가 → 없으면 MINOR, 내용이 현실과 다르면 MAJOR
- [ ] **결정이 본문에 숨어 있음** — 중요한 결정이 서술 문단 중간에만 있고 요구사항으로 승격되지 않았는가
- [ ] **합의 여부 불명** — "~하기로 함"의 주체가 없는 항목. 누가 합의했는지 알 수 없으면 실행 단계에서 뒤집힌다
- [ ] **영업/제안 문구 혼입** — 제안서에서 온 문서는 실현 근거 없는 약속이 섞인다. 요구로 오인되면 CRITICAL
- [ ] **첨부·참조 부재** — "별첨 참조"인데 별첨이 없는 항목
- [ ] **단위·기준 누락** — 수치는 있는데 단위·측정 조건이 없음 (특히 성능·전기 사양)
- [ ] **버전 충돌** — 같은 항목이 문서 내 두 곳에서 다른 값

## 2. 착수 가능성 판정 (이 스킬의 핵심 질문)

"이 문서로 지금 개발을 시작하면 무엇이 터지는가"에 답한다.

- [ ] 첫 작업을 정할 수 있는가 (무엇부터 할지 문서에서 도출되는가)
- [ ] 완료를 판정할 수 있는가 (AC 또는 그에 준하는 기준)
- [ ] 범위 밖을 거절할 근거가 있는가 (비범위 또는 그에 준하는 경계)
- [ ] 치명적 미지수가 문서에 드러나 있는가 (숨어 있는 것이 더 위험)
- [ ] 이해관계자와 결정 주체를 알 수 있는가

5개 중 **2개 이상 아니오 → 재작성 권고**.

## 3. 문서 종류별 추가 점검

### PRD
- [ ] 요구가 아니라 해법이 적혀 있지 않은가 (설계 결정이 요구로 위장)
- [ ] 사용자·운영 주체가 빠지지 않았는가
- [ ] 성공 지표가 문서 목적과 연결되는가

### PLAN
- [ ] 작업이 요구사항과 연결되는가 (연결이 없으면 근거 없는 작업)
- [ ] 순서가 실제 의존을 반영하는가 (통합·검증이 마지막에 몰려 있으면 리스크)
- [ ] 검증·문서·배포 작업이 있는가 (구현만 있는 계획은 반드시 늦는다)
- [ ] 지어낸 일정·공수가 있는가 (`estimation-policy.md` 위반)

### 체크리스트
- [ ] 완료 판정 근거 칸이 있는가 (없으면 "했다고 치는" 완료를 막을 수 없다 → MAJOR)
- [ ] 구현과 검증 주체가 분리되는가
- [ ] 이미 `[x]`인 항목에 근거가 있는가 → 없으면 그 완료는 신뢰할 수 없다

## 4. 리포트에 반드시 남길 것

- **검수 범위의 한계**: 상위 문서 미확보, 첨부 부재, 기계 검증 불가 등 — 검수가 못 본 영역을 숨기지 않는다
- **추정한 것**: 프로파일 추정, 문서 종류 추정
- **지적하지 않은 것 중 신경 쓰인 것**: 경계 규칙상 지적하지 않았지만 알아둘 사항은 INFO로
