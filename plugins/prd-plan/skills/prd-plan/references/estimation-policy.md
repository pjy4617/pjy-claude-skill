# 산정 정책 — 지어낸 일정 금지

> LLM이 만든 "3인일", "3월 2주차", "약 2주 소요"는 **근거가 없다.**
> 그럴싸한 숫자는 검증되지 않은 채 그대로 보고서로 올라가고, 어긋났을 때 책임 소재만 흐린다.
> 이 정책은 그 경로를 원천 차단한다.

## 금지 (위반 시 검수에서 MAJOR)

| 금지 | 예 |
|------|-----|
| 절대 날짜 | `2026-03-15 완료`, `3월 2주차`, `Q2 중` |
| 시간 단위 공수 | `3인일`, `16시간`, `2주 소요`, `약 한 달` |
| 인원 배정 | `프론트 2명 투입`, `담당: 김OO` (사용자가 지정한 경우 제외) |
| 속도 가정 | `주당 5 스토리포인트 소화 가정` |
| 확률 표현의 정량화 | `85% 확률로 3월 완료` |

## 허용 (기본 표기)

| 항목 | 표기 | 비고 |
|------|------|------|
| 작업 크기 | **S / M / L / XL** | 상대 크기. XL은 분해 대상 |
| 순서 | **상대 순번** `D+0`, `D+1`... 또는 `1단계/2단계` | 착수일 기준 상대값. 캘린더 날짜 아님 |
| 마일스톤 | **라벨 + 완료 조건** (M1, M2...) | 날짜 없음 |
| 역할 | **역할명** (프론트, 백엔드, 펌웨어, 검증) | 사람 이름 아님 |
| 불확실성 | **높음/중간/낮음** + 사유 | 확률값 아님 |

## 사용자가 제공한 값은 기록한다

일정·인원은 **사용자가 말한 경우에만** 기재하고, 반드시 출처를 남긴다.

```markdown
## 6. 가정 · 미결 의존

| 가정 | 출처 | 깨질 경우 영향 |
|------|------|----------------|
| 납기 4월 말 | 사용자 인터뷰 (2차 라운드) | M3 이후 작업 전면 재조정 |
| 프론트 1명 · 백엔드 1명 | 사용자 제공 | 병행 가능 작업 수 제한 |
| PCB 리드타임 2주 | 사용자 제공(벤더 견적) | M2→M3 사이 직렬 대기 발생 |
```

출처가 없는 값은 가정 표에도 쓰지 않는다. 필요하면 미결 이슈로 올린다.

## 일정이 꼭 필요할 때

사용자가 "일정표를 달라"고 하면:

1. **먼저 알린다** — 근거 없는 날짜는 만들지 않으며, 필요한 입력은 ① 착수일 ② 가용 인원/역할 ③ 외부 납기·리드타임이라고 설명한다
2. 사용자가 입력을 주면 **상대 순번 → 캘린더 매핑**만 수행하고, 매핑 근거를 문서에 남긴다
3. 입력을 못 준다면 **의존 사슬 기반 상대 일정**(최장 경로 n단계, 병행 가능 구간 표시)까지만 제시한다

이 방식은 "언제 끝나냐"에 답하지 못하는 것이 아니라, **무엇이 결정되면 답할 수 있는지**를 명확히 하는 것이다.

## 규모 산정 시 체크

- [ ] 이 작업의 불확실성이 큰가 → 크면 등급을 올리지 말고 **분해**한다 (XL은 등급이 아니라 신호)
- [ ] 외부 의존(부품·승인·타 팀)이 있는가 → 규모가 아니라 **차단 요인**으로 표기
- [ ] 검증까지 포함한 크기인가 → 검증은 별도 TASK이므로 포함하지 않는다
- [ ] 비슷한 작업 간 등급이 일관되는가 (같은 성격 작업이 S와 L로 흩어져 있으면 재검토)
