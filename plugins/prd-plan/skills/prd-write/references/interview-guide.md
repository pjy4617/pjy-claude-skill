# 인터뷰 가이드 — 메인 세션 전용

> **이 인터뷰는 서브에이전트가 할 수 없다.** 서브에이전트에는 AskUserQuestion이 없으므로, 질문은 반드시 메인 세션에서 하고 확정 답변만 넘긴다.

## 원칙

1. **한 번에 최대 4문항**(AskUserQuestion 상한), 총 2~3회로 끝낸다. 인터뷰가 길어지면 사용자가 대충 답한다.
2. **답을 아는 질문은 하지 않는다.** 입력 자료·코드베이스에서 확인 가능한 것은 읽어서 채우고 "이렇게 이해했습니다"로 확인만 받는다.
3. **선택지를 준다.** 자유서술을 요구하면 답이 모호해진다. 옵션 2~4개 + Other.
4. **"모른다"는 유효한 답이다.** 모른다고 하면 즉시 미결 이슈로 등록하고 다음으로 넘어간다. 캐묻지 않는다.
5. 비범위는 **반드시 직접 묻는다.** 사용자는 먼저 말해주지 않는다.

## 라운드 1 — 뼈대 (4문항)

| 헤더 | 질문 | 옵션 예시 |
|------|------|-----------|
| 문제 | 지금 무엇이 문제이고, 왜 지금 해결해야 하나요? | 수작업 반복/기존 시스템 한계/신규 요구 대응/원인 규명 필요 |
| 사용자 | 이걸 실제로 쓰는 사람은 누구인가요? | 사내 엔지니어/생산 현장 작업자/외부 고객/자동화 시스템(무인) |
| 성공 | 무엇이 되면 성공인가요? (측정 기준) | 처리 시간 단축/불량률 감소/신규 기능 제공/타당성 판정 |
| 규모 | 이번 범위는 어느 정도인가요? | PoC(버려도 됨)/내부 사용 수준/양산·상용 수준 |

## 라운드 2 — 경계와 제약 (4문항)

| 헤더 | 질문 | 비고 |
|------|------|------|
| 비범위 | 이번에 **하지 않을** 것을 정해주세요 | 최소 3개를 유도. "다 필요하다"면 우선순위 질문으로 전환 |
| 제약 | 반드시 지켜야 하는 제약이 있나요? | 부품/플랫폼 지정, 기존 시스템 호환, 규정·인증, 언어·프레임워크 |
| 기존 자산 | 참고할 기존 문서·코드·보드가 있나요? | 경로를 받으면 모드 B/C로 전환 |
| 리스크 | 가장 불확실하거나 걱정되는 부분은? | 그대로 리스크 섹션 초안이 된다 |

## 라운드 3 — 프로파일별 보강 (필요 시에만)

**software / frontend (React)**: 화면 목록, UI 라이브러리(Fluent UI v9 vs shadcn — 프로젝트당 택1), 실시간 갱신 필요 여부(폴링/WebSocket), 대상 브라우저·해상도, 접근성(현장 장비면 장갑 조작·터치 타겟)
**software / backend (C++·C#·Python)**: 언어와 런타임 버전, 실행 형태(서비스/CLI/라이브러리), 제공·소비 인터페이스(REST/gRPC/IPC), 부하와 지연 목표, 실시간성(GC 허용 여부), 장애 시 동작
**software / full-stack**: 위 둘 + **API 계약을 지금 정할 수 있는가**(못 정하면 OPEN 이슈로 명시)
**hardware-firmware**: 인터페이스 종류, 전원 소스, 제어 주기/정밀도 요구, 폼팩터 제약, 인증 필요 여부
**research-PoC**: 가설, 베이스라인, 가용 데이터/시뮬레이터, **중단 기준**

## 확정 블록 (작성 에이전트에 넘길 형식)

```markdown
## 인터뷰 확정 사항
- 문제: <사용자 답변 그대로. 요약하되 왜곡 금지>
- 사용자: ...
- 성공 지표: ...
- 필수 범위: ...
- 비범위: ...
- 제약: ...
- 리스크/미지수: ...
- 프로파일 보강: <라운드 3 답변>
- 사용자가 "모른다"고 한 항목: <그대로 나열 — 미결 이슈가 된다>
- 인터뷰에서 다루지 못한 항목: <생략된 경우>
```

## 하지 말아야 할 것

- 사용자가 말하지 않은 요구를 "일반적으로 필요하니까" 추가하기 → 범위 팽창의 시작
- 답변을 매끄럽게 다듬으며 조건을 빼먹기 → 원문 표현을 살린다
- 확정되지 않은 값을 "일단 이렇게 가정하고"로 넘어가기 → 가정으로 남기려면 **가정 섹션에 출처와 함께** 기록
- 사용자가 "알아서 해줘"라고 할 때 그대로 진행 → 최소한 프로파일과 비범위는 확인한다
