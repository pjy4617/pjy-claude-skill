# PRD 코어 규격 — 모든 프로파일 공통

프로파일별 추가 섹션은 `prd-profiles.md` 참조. 여기 있는 것은 **어떤 프로파일이든 반드시 있어야 하는 것**이다.

## 파일 위치·이름

```
docs/prd/PRD-<slug>.md          # slug은 kebab-case 주제명
docs/reviews/REVIEW-<slug>-r<N>.md
```

## 프론트매터 (필수)

```yaml
---
id: PRD-<slug>
title: <문서 제목>
profile: software | hardware-firmware | research-PoC
stack: frontend | backend | full-stack      # profile이 software일 때만
status: draft | in-review | approved        # approved는 사용자 승인으로만
version: 1.0
owner: <요청자/책임자 — 미확보면 "미정">
approved_by: <승인 시에만>
approved_at: <승인 시에만, 사용자가 제공한 날짜만>
changelog:
  - "1.0 draft 초안 작성"
  - "1.1 R1 리뷰 반영 (C2/M3 해소)"   # 오래된 것부터 오름차순. 승인은 마지막 줄에 별도 기록
---
```

> **에이전트가 날짜를 지어내지 않는다.** `approved_at`은 사용자가 명시한 경우에만 기록하고, 아니면 필드를 생략한다.

## 섹션 구성 (순서 고정)

| # | 섹션 | 필수 | 내용 |
|---|------|:---:|------|
| 1 | 개요 | ✅ | 3~5문장. 이 문서를 처음 보는 사람이 무엇을 만드는지 알 수 있어야 함 |
| 2 | 배경 · 해결할 문제 | ✅ | 현재 상태와 문제. "왜 지금인가" 포함 |
| 3 | 사용자 · 이해관계자 | ✅ | 역할별로. 운영/유지보수 주체 누락 주의 |
| 4 | 성공 지표 | ✅ | 측정 가능한 지표. 측정 방법과 기준선 포함 |
| 5 | 범위 (In Scope) | ✅ | 이번에 하는 것 |
| 6 | **비범위 (Out of Scope)** | ✅ | **최소 3항목.** 안 하는 것 + 안 하는 이유 |
| 7 | 요구사항 | ✅ | REQ 블록들 (아래 규격) |
| 8 | 제약 조건 | ✅ | 기술·환경·규정·호환성. 프로파일별 필수 항목 있음 |
| 9 | 가정 | ✅ | 참이라고 전제한 것 + 출처. 깨지면 무엇이 무너지는지 |
| 10 | 리스크 | ✅ | 영향/발생가능성/완화책. 최소 3건 |
| 11 | 미결 이슈 | ✅ | OPEN-### 표. 없으면 "없음"이라고 명시 |
| 12 | 참고 자료 | — | 입력 자료 경로·인덱스·매뉴얼 다이제스트 ID |

## 요구사항(REQ) 블록 규격

기계 파싱(`check_traceability.py`) 대상이므로 **형식을 지킨다**.

```markdown
### REQ-001 — 서보 온 시퀀스 자동화

- **강도**: MUST            <!-- MUST | SHOULD | MAY -->
- **설명**: 운전 개시 시 축 전체의 서보 온을 정해진 순서로 수행해야 한다.
- **수용 기준**:
  - AC-001-1: 서보 온 요청 후 전 축이 3초 이내 Ready 상태가 된다.
  - AC-001-2: 임의 축이 실패하면 이미 온 된 축을 역순으로 오프하고 오류 코드를 반환한다.
- **근거**: 인터뷰 확정 사항 / <입력 자료 경로:라인>
- **비고**: (선택) 제외 조건·예외
```

규칙:
- ID는 `REQ-` + 3자리 연번, **재사용·재배치 금지**. 삭제 시 블록을 남기고 `- **상태**: 삭제됨 (R2)` 표기
- **AC 없는 REQ 금지.** AC는 관측 가능한 조건이어야 한다 (숫자·상태·에러코드·산출물 존재)
- 한 REQ에 요구를 두 개 이상 넣지 않는다 (분리하면 추적이 산다)
- 강도 표기: MUST(필수) / SHOULD(권장) / MAY(선택)

### 나쁜 AC vs 좋은 AC

| ❌ | ✅ |
|---|---|
| 응답이 빨라야 한다 | p95 응답 200ms 이하 (100 동시요청, 스테이징 기준) |
| 안정적으로 동작한다 | 24시간 연속 운전 중 통신 단절 0회, 재시도 로그로 검증 |
| 사용자 친화적 UI | 신규 사용자가 매뉴얼 없이 3분 내 1회 사이클 완료 (5인 테스트 중 4인 이상) |

## 미결 이슈 표

```markdown
| ID | 항목 | 현재 상태 | 필요한 결정 | 결정 주체 | 영향받는 REQ |
|----|------|-----------|-------------|-----------|--------------|
| OPEN-001 | 통신 프로토콜 | EtherCAT/TSN 미정 | 슬레이브 벤더 확정 | 사용자 | REQ-004, REQ-011 |
```

본문에서 미정 값을 쓸 때는 `(미정 — OPEN-001)`로 표기한다. 임의 값을 넣고 나중에 고치는 방식을 금지한다.

```

빠르게  안정적으로  효율적으로  충분히  일반적으로  대략  등의
```

이 단어들이 요구사항·AC에 남아 있으면 수치·조건으로 바꾸거나 미결 이슈로 올린다. (배경·개요 서술에서는 허용)

```bash
grep -nE "등등|기타|적절히|필요시|가능한 한|사용자 친화적|빠르게|안정적으로" docs/prd/PRD-<slug>.md
```
