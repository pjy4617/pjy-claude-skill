# 대용량 문서 처리 — doc-atomize 연동 규약

PRD/PLAN은 프로젝트가 진행될수록 커지고, 커진 문서를 매 라운드 통째로 읽으면 검수 비용이 문서 크기에 비례해 늘어난다. `doc-atomize`(무손실 분할)로 이를 끊되, **타이밍을 틀리면 오히려 비싸진다.**

## 임계값 — **바이트 기준 40KB 초과**

| 대상 | 임계값 | 판단 |
|------|--------|------|
| PRD · 승인된 PLAN | **40KB 초과** | 승인 후 분할 |
| 입력 자료(기획서·회의록·규격서) | **40KB 초과** | 읽기 전에 분할 |
| **체크리스트** | — | **크기와 무관하게 분할하지 않는다** (아래 참조) |
| 그 미만 | — | 분할하지 않는다 (인덱스 유지비가 더 크다) |

### 읽히는 문서만 분할한다

판단 기준은 크기가 아니라 **문서의 성격**이다.

| | 읽히는 문서 (PRD·승인된 PLAN) | 쓰이는 문서 (체크리스트) |
|---|---|---|
| 변경 빈도 | 요구가 바뀔 때만 | **항목을 체크할 때마다** |
| 조회 패턴 | 특정 절만 (조각 1~3개로 충분) | **전수 집계**(진척률·다음 착수 후보) |
| 기계 조회 | 인덱스 경유 | `check_traceability.py`가 **원본을 직접 파싱** |
| 판정 | **분할한다** | **분할하지 않는다** |

체크리스트를 분할하면 자동 갱신 훅과 맞물려 **체크 하나 누를 때마다 재분할**이 돌고, 정작 주 조회인 전수 집계에서는 조각이 이득을 주지 못한다. 원자화의 전제는 "자주 읽히고 드물게 바뀌는 문서"인데 체크리스트는 정반대다.

**체크리스트가 커지면** 원자화가 아니라 **마일스톤 단위 파일 분리**로 간다:
`CHECKLIST-<slug>-M1.md`, `-M2.md` … 이렇게 나누면 작업 중인 마일스톤 파일만 열면 되고, 쓰기 대상 문서를 파생물과 원본으로 이중화하지 않아도 된다.

```bash
wc -c docs/prd/PRD-x.md      # 40960 초과면 분할 대상
wc -l docs/prd/PRD-x.md      # 줄 수는 참고값 — 판정 기준이 아니다
```

> **줄 수로 판정하지 않는다.** 읽기 비용은 줄 수가 아니라 바이트(≈토큰)에 비례한다.
> 표와 짧은 줄이 많은 문서는 400~500줄이어도 15~20KB로 통독이 더 싸다 — 이런 문서를 분할하면
> 인덱스 유지비와 조각 왕복만 늘어난다. 40KB는 대략 1만 토큰으로, 이 지점부터 분할이 이익이다.
> 애매하면(30~40KB) 분할하지 않는다 — 분할은 되돌리는 비용이 더 크다.

## 타이밍 3구간 (핵심)

### ① 입력 인제스트 — 읽기 **전에** 분할

기존 기획서·회의록·규격서가 크면 먼저 분할하고, 작성 에이전트에는 **원본이 아니라 `<doc-id>.index.md` 경로**를 넘긴다. 에이전트는 인덱스를 읽고 관련 조각 1~3개만 Read한다.

```
/doc-atomize <입력자료.md>
→ 위임 프롬프트의 "입력 자료 경로"에 .claude/atomized/<id>/<id>.index.md 기재
```

PDF·CHM·DOCX 등 마크다운이 아닌 원본은 `doc-atomize`가 아니라 **`manual-digest`** 담당이다(요약 등록). 코드베이스 역공학도 manual-digest의 codebase 인제스트를 쓴다.

### ② 검수 루프 중 — **분할 금지**

라운드마다 문서가 수정되므로, 분할해 두면 매 라운드 `--update` 재분할이 필요하고 조각 경계가 흔들려 리뷰 리포트의 `파일:라인` 근거가 어긋난다.

**루프가 도는 동안은 단일 파일을 유지한다.** 문서가 커서 검수가 무겁다면 분할이 아니라 **문서 분리**(예: 요구사항 부록을 별도 PRD로)를 검토한다.

### ③ 승인 후 — 분할하고 다운스트림은 인덱스로 조회

`status: approved`가 된 뒤에만 분할한다. 이후 `prd-plan`·`prd-checklist`·다른 도메인 스킬은 인덱스를 진입점으로 쓴다.

```
/doc-atomize docs/prd/PRD-<slug>.md
→ .claude/atomized/prd-<slug>/prd-<slug>.index.md
```

**모드 선택**

| 모드 | 결과 | 언제 |
|------|------|------|
| 기본(파생물) | `.claude/atomized/<id>/` 에 인덱스+조각, `docs/`의 원본 유지 | **기본값.** git에 PRD 원본을 그대로 남기고 싶을 때 |
| `--in-place` | `docs/prd/` 자리에 인덱스+조각 재구성(검증 통과 시 원본 제거) | 문서 자체를 조각 정본으로 운영할 때. git 클린 상태에서만 |

승인 후 문서가 다시 수정되면(요구 변경) **doc-atomize의 PostToolUse 훅이 변경 조각만 자동 재생성**한다 — 등록된 원본을 Edit/Write 하는 순간 갱신되므로 `--update`를 따로 부를 필요가 없다. 훅이 꺼져 있거나 `split_md.py`를 찾지 못하면 안내만 오므로 그때 `/doc-atomize --update <id>`를 실행한다.

훅이 해주지 않는 것 두 가지는 **사람이 마무리한다**:
1. 본문이 바뀐 조각에 붙는 `⚠️` — 요약을 다시 쓰고 `reindex`
2. 체크리스트 영향 — `/prd-checklist --sync`로 재검증 항목 추가

## 미설치 폴백

`doc-atomize`가 없으면 **작업을 중단하지 않는다.**

```bash
ls ~/.claude/plugins/**/doc-atomize/skills/doc-atomize/assets/split_md.py 2>/dev/null
```

없으면:
1. 원본을 그대로 사용한다 (통독)
2. 최종 보고에 `분할: 미적용 (doc-atomize 미설치)` 명시
3. 한 번만 안내: `/plugin install doc-atomize@pjy-skills` 후 `/doc-atomize-setup`

## 인덱스를 받은 에이전트의 규칙

- **작성** 에이전트: 인덱스의 라우팅 힌트·키워드 역색인으로 **필요한 조각만** 읽는다
- **검수** 에이전트: 검수는 전수 검사다. 인덱스가 주어져도 **모든 조각을 순회**한다. 선택 읽기로 검수 범위를 줄이지 않는다
- 인용할 때는 조각 파일 경로:라인을 쓴다 (조각이 정본이므로 원문 그대로 인용 가능)
